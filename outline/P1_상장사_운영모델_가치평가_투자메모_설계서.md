## 0. 이번 개정의 원칙

### 0.1 사용자 전제

FinDone은 본인이 직접 사용하려고 만든 제품이다. 따라서 외부 사용자 성장이나 retention을 억지로 입증하는 프로젝트로 바꾸지 않는다. 이 전제는 외부 연구의 결론이 아니라 **사용자가 밝힌 프로젝트 목적**이다.

- FinDone이 증명하는 것: 금융 문제정의, 도메인 구조화, AI 활용, 제품 구현, 품질관리
- P1이 새로 증명할 것: 재무제표 해석, 산업·기업 분석, driver-based forecast, valuation, downside 판단, 경영진 문서

### 0.2 기존 문서에서 제거한 임의 기준

다음 값은 보편적인 CFA·IFRS·모델리스크 기준이 아니므로 품질 기준에서 제거했다.

| 기존 임의 기준 | 변경 후 결정 원리 |
|---|---|
| 결제·핀테크를 기본 산업으로 지정 | 관련 직무의 공식 역할·방법론, 금융 의사결정 가치, 공개자료 적합성으로 결정 |
| 후보기업 개수와 가중 점수, 합격점 | 필수 근거 gate를 모두 통과하는지로 결정 |
| 고정 역사적 분기 수 | 비교가능한 사업·회계기간, 계절성, 경기순환, 구조적 단절로 결정 |
| 고정 전망 분기·연도 수 | 의사결정 horizon, cyclicality, 경쟁우위·정상화 기간, 데이터 신뢰도로 결정 |
| 고정 프로젝트 주수와 단축판 | 산출물 의존관계와 데이터 feasibility를 확인한 뒤 일정 산정 |
| 고정 peer 수 | 경제적·회계적 비교가능성 기준을 충족하는 기업으로 결정 |
| Base/Upside/Downside 정확히 세 개 | 실제로 중요한 위험과 catalyst를 포착하는 일관된 복수 경로로 결정 |
| 고정 sensitivity 폭·step·표 개수 | 역사적 분포, 회사 가이던스, 시장근거, 공식 stress, break-even으로 결정 |
| 고정 backtest 기간·횟수 | 사용 가능한 독립 forecast origin, 모델 목적, 데이터 빈도로 결정 |
| 고정 memo 페이지·deck 장수·논점 개수 | 독자가 분석을 비판할 수 있을 만큼 충분하고 명료한 내용으로 결정 |
| 고정 review 횟수 | 모델 중요도·복잡성·변경 정도에 비례하는 독립적 검토로 결정 |
| 100점 평가표와 80점 공개선 | 비보상적 release gate로 결정 |

고정 숫자가 실무 편의를 위해 필요해지는 경우에는 `외부 표준`으로 쓰지 않는다. 실제 데이터·의사결정 목적에서 산출한 값, 근거, 기준일, 변경 조건을 assumption log에 남긴다.

### 0.3 의사결정 라벨

문서와 모델의 주요 선택에는 다음 라벨 중 하나를 붙인다.

| 라벨 | 의미 | 허용 근거 |
|---|---|---|
| `[STD]` | 외부 원칙 | 공식 회계·공시·전문직·모델리스크 기준 |
| `[EVID]` | 대상회사·시장 증거 | 공시, 정정공시, 공식 IR, 정부·거래소 데이터 |
| `[USER]` | 사용 목적·커리어 제약 | 사용자가 명시한 목표와 선호 |
| `[CALC]` | 공개값에서 파생 | 재현 가능한 산식과 원천 셀 |
| `[JUDG]` | 전문판단 | 대안, 선택 이유, 민감도, 한계를 문서화한 판단 |

`[JUDG]`는 근거 없는 임의 선택을 뜻하지 않는다. 외부 원칙이 단일 숫자를 정하지 않는 영역에서, 관련 증거와 대안을 기록한 판단을 뜻한다.

### 1.2 적용상 주의

- CFA 자료는 전문 분석 원칙이다. 특정 회사의 정답이나 고정 숫자를 제공하지 않는다.
- IFRS는 재무보고 기준이다. 포트폴리오 모델의 역사적·전망 기간을 정하는 규정이 아니다.
- SR 26-2는 은행 모델리스크 지침이며 연준은 총자산 300억 달러 초과 감독대상 은행에 가장 관련된다고 밝힌다. P1이 규제 준수를 주장하지 않고, 전통적 재무예측 모델의 위험기반 검증 원칙만 비례 적용한다. [SR 26-2 발행문](https://www.federalreserve.gov/supervisionreg/srletters/SR2602.htm)은 2026년에 종전 SR 11-7을 대체한다고 명시하고, 본문은 생성형·에이전틱 AI를 적용 범위에서 제외한다. 세부 AI 사용은 별도의 출처 검증·인간 검토 통제로 다룬다.
- Damodaran 자료를 사용할 경우 학술·실무 판단 보조자료로 표시하며 회계·규제 의무로 표현하지 않는다.

## 2. 프로젝트 목적과 의사결정 질문

### 2.1 목적

P1의 목적은 다음 연결을 재현 가능하게 증명하는 것이다.

```text
공식 원천 → 정규화된 사실 → 사업 driver → 재무 전망
→ 목적에 맞는 가치평가 → 위험·반대논리 → 조건부 의사결정
```

CFA의 valuation process인 사업 이해, 성과 전망, 적절한 valuation model 선택, valuation 변환, 결론 적용을 P1의 뼈대로 사용한다. 근거: [CFA Equity Valuation: Applications and Processes](https://www.cfainstitute.org/insights/professional-learning/refresher-readings/2026/equity-valuation-applications-and-processes).

### 2.2 핵심 질문

대상기업과 독자를 확정한 뒤 다음 문장을 구체화한다.

> `[as-of date]`에 이용 가능했던 정보만 볼 때, 이 기업의 가치와 의사결정을 좌우하는 검증 가능한 driver는 무엇이며, 어떤 조건에서 현재 결론이 바뀌는가?

투자자용이면 가격에 반영된 기대와 intrinsic/relative value를 다룬다. CEO·Chief of Staff용이면 자원배분, build–buy–partner, 시장진입, 비용·현금 우선순위 등 실제 decision을 다룬다. Valuation conclusion의 적용은 목적에 달라진다는 CFA 원칙을 따른다.

### 2.3 하지 않을 것

- 비공개 스타트업의 미공개 매출·ARR·CAC·LTV·기업가치를 사실처럼 역산하지 않는다.
- 한 방법의 한 점 추정치를 정답처럼 제시하지 않는다.
- 기사·검색요약·LLM 출력만으로 핵심 숫자를 확정하지 않는다.
- 실제 회사의 의사결정을 지원했거나 투자 성과를 냈다고 과장하지 않는다.
- 공개 당시 존재하지 않았던 정정값을 과거 backtest에 넣지 않는다.
- 모델의 의도된 사용범위를 넘어선 투자·회계·법률 자문으로 표현하지 않는다.

## 3. 대상기업 선정: 점수제가 아닌 근거 gate

### 3.1 산업은 미리 고정하지 않는다

결제·핀테크, AI·SW, 헬스케어, 소비재 등 어떤 산업도 자동 기본값으로 두지 않는다. 각 후보는 아래 세 종류의 근거로 평가한다.

- `[USER]` 사용자가 선호하는 금융 도메인과 관련 직무군
- `[STD]` CFA·AFP 등 공식 역할·방법론이 설명하는 반복 가능한 분석 절차
- `[EVID]` 상장사 공시에서 반복 추적 가능한 재무·운영 driver와 비교가능 기간

case는 현재 지원기업이나 열린 공고에 맞춰 고르지 않는다. 먼저 금융·기업재무 의사결정 가치, 공개데이터 깊이와 검증가능성으로 대상을 정하고, 완성 후 특정 지원서에서는 검증된 산출물 중 해당 JD와 겹치는 부분만 사후 mapping한다.

### 3.2 필수 gate

후보기업은 점수를 합산하지 않고 다음 gate를 순서대로 통과해야 한다.

#### Gate A — 금융 의사결정·직무 관련성

- CEO Staff·전략·FP&A·CorpDev·Equity/Credit RA 등 관련 직무군에서 반복되는 분석 절차를 공식 역할·방법론 reference로 확인할 수 있다.
- 분석대상의 사업 economics와 금융 의사결정 질문을 한 문장으로 정의할 수 있다.
- 특정 지원회사 선호가 아니라 기업의 driver·현금·가치·위험과 연결되는 방식으로 금융 도메인 관련성을 설명한다.

#### Gate B — 원천자료와 provenance

- 공시 원문, XBRL/재무정보, 시장정보의 공식 source path가 존재한다.
- 접수번호, 보고기간, 연결·별도, 통화·단위, 정정 여부를 보존할 수 있다.
- 운영 KPI가 없다면 재무 line 또는 다른 검증 가능한 forecast object로 대체할 수 있으며 한계를 명시할 수 있다.

#### Gate C — 비교가능성

- 회계정책, 세그먼트, 결산월, 중단영업, 대형 M&A·분할 등 구조적 단절을 식별할 수 있다.
- 단절 전후를 하나의 연속 시계열로 볼지, 별도 regime으로 나눌지 근거를 기록할 수 있다.
- 연결과 별도, 분기와 누적, 원통화와 환산값을 섞지 않을 수 있다.

#### Gate D — 의사결정 가능성

- 공개자료로 검증 가능한 driver와 material risk를 식별할 수 있다.
- 모델 결과가 실제 조건부 결정 또는 monitoring question으로 이어진다.
- 데이터가 허용하는 valuation 방법과 허용하지 않는 방법을 구분할 수 있다.

#### Gate E — 실행 가능성

- 원천 수집·정규화 pilot을 수행해 가장 큰 병목을 확인했다.
- 핵심 산출물과 선택 산출물을 분리할 수 있다.
- 일정은 pilot의 실제 처리량과 의존관계로 추정할 수 있다.

필수 gate가 실패하면 다른 항목의 강점으로 상쇄하지 않는다. 실패 이유와 대체기업 검토 근거를 decision log에 남긴다.

### 3.3 선정 기록 템플릿

| 필드 | 내용 |
|---|---|
| Candidate | 회사명·ticker·거래소 |
| Role/domain evidence | 공식 역할·방법론 URL·접근일·관련 분석 절차 요약 |
| Decision question | 이 회사로 답할 조건부 의사결정 |
| Official sources | DART/KIND/IR/KRX 등 실제 링크 |
| Forecast objects | 공개 driver 또는 재무 line |
| Structural breaks | 회계·사업 변화와 처리안 |
| Valuation candidates | 적용 가능 방법과 제외 방법 |
| Material limitations | 결론 사용범위를 제한하는 요소 |
| Gate result | 각 gate의 pass/fail과 근거 |

## 4. 데이터와 provenance

### 4.1 source hierarchy

1. 공시 원문: DART 또는 KIND의 해당 접수번호 문서
2. 구조화 재무데이터: OpenDART XBRL 원본 또는 전체 재무제표 API
3. 시세·상장주식수·기업행위: KRX Data Marketplace와 KIND
4. 회사 공식 IR·실적발표: 세그먼트·KPI·전략 설명 보완
5. 한국은행 ECOS·KOSIS 등 공식 통계: 거시·산업 driver
6. SEC EDGAR 등 해외 규제기관 공시: 해외 비교기업
7. 2차 자료: 후보 발견과 맥락 파악용; 핵심 숫자는 1차 출처로 재확인

OpenDART는 DART 공시 원문 XML, 정기보고서 주요 재무계정과 XBRL 자료를 제공한다. [OpenDART 소개](https://opendart.fss.or.kr/intro/main.do), [재무정보 개발가이드](https://opendart.fss.or.kr/guide/main.do?apiGrpCd=DS003), [공시 원본파일 API](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019003).

시장·기업행위 자료는 [KRX Data Marketplace](https://data.krx.co.kr/contents/MDC/MAIN/main/index.cmd)와 [KIND](https://kind.krx.co.kr/disclosure/searchdisclosurebycorp.do?method=searchDisclosureByCorpMain)를 사용한다.

### 4.2 원천행 필드

OpenDART 전체 재무제표 API가 제공하는 접수번호, 연결·별도, 재무제표 구분, account ID, 기간, 3개월·누적 금액, 통화를 잃지 않도록 다음 lineage를 보존한다. 필드의 구체 구현은 데이터 형식에 맞추되 의미를 생략하지 않는다. 근거: [OpenDART 전체 재무제표 API](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS003&apiId=2019020).

```text
source_system / source_type
corp_code / stock_code / issuer_legal_name
report_name / rcept_no / rcept_dt / report_code
original_or_amended / supersedes_rcept_no / filing_url
fs_div / statement_type
taxonomy_namespace / taxonomy_version
account_id / account_label_raw
period_start / period_end / period_kind / period_view
currency / unit_scale / raw_value
retrieved_at_kst / raw_file_hash
transform_version / mapping_rule_id
derived_flag / derivation_formula / review_status
```

### 4.3 주장·숫자 태그

| 태그 | 의미 |
|---|---|
| `[F]` | 원문에서 직접 확인되는 fact |
| `[D]` | 원문 값에서 재현 가능하게 계산한 derived value |
| `[A]` | 전망·valuation을 위한 assumption |
| `[I]` | 복수 사실을 연결한 inference |
| `[R]` | 조건부 recommendation |
| `[M]` | 직접 수행한 test·measurement 결과 |

### 4.4 정정공시와 데이터 vintage

값을 덮어쓰지 않고 접수번호 단위로 append-only 저장한다.

- `as_reported`: 각 분석 기준일에 실제로 이용 가능했던 공시
- `latest_restated`: 현재 기준 최신 정정·재작성 비교수치

현재 valuation에는 `latest_restated`를 사용하고, 과거 예측 backtest에는 해당 forecast origin의 `as_reported`를 사용한다. 정정 전후의 값, 영향받은 기간·비율·결론, supersession 관계를 change log에 기록한다. 근거: [OpenDART 공시검색 API](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019001), [IAS 8](https://www.ifrs.org/issued-standards/list-of-standards/ias-8-basis-of-preparation-of-financial-statements/).

### 4.5 연결·별도 선택

- 그룹 전체의 영업·현금흐름·기업가치를 분석하면 연결재무제표를 사용한다.
- 모회사 자체의 배당여력·법정자본·채무상환처럼 parent-only 질문이면 별도재무제표를 사용한다.
- 연결이 없는 회사는 별도를 사용하고 그 사실을 표시한다.
- 하나의 시계열·peer multiple·valuation bridge에서 두 범위를 혼합하지 않는다.

선택은 관행적 기본값이 아니라 **분석 unit of account**에 따른다. 근거: [IFRS 10](https://www.ifrs.org/issued-standards/list-of-standards/ifrs-10-consolidated-financial-statements/), [IAS 27](https://www.ifrs.org/issued-standards/list-of-standards/ias-27-separate-financial-statements/).

### 4.6 분기·누적 정규화

- 재무상태표는 시점값이므로 기간 flow처럼 합산·차감하지 않는다.
- 손익·포괄손익에 공시된 당기 기간값이 있으면 그 값을 사용한다.
- 기간값이 없고 누적값만 있으면 연속 누적기간의 차이로 개별기간 flow를 파생한다.
- 현금흐름·자본변동 flow도 같은 원리로 처리하되 원천기간을 확인한다.
- 모든 파생값에 원천 접수번호, 기간, 산식, `derived_flag`를 남긴다.
- 분기값과 YTD를 한 성장률·차트·모델 line에 혼합하지 않는다.

중간재무제표가 현재 중간기간과 YTD 및 비교기간을 구분한다는 [IAS 34](https://www.ifrs.org/issued-standards/list-of-standards/ias-34-interim-financial-reporting/)와 OpenDART의 기간 필드를 따른다.

### 4.7 XBRL mapping

- `taxonomy namespace + account_id + period context`를 기본 식별자로 보존한다.
- 회사 고유 extension tag를 계정명 유사성만으로 표준계정에 자동 병합하지 않는다.
- 원 tag·label, mapping 근거, 작성자, 검토상태를 보존한다.
- taxonomy 또는 mapping 변경은 버전 관리한다.

IFRS Foundation은 표준 taxonomy tag가 디지털 비교가능성을 돕고 불필요한 entity-specific extension이 비교를 어렵게 할 수 있다고 설명한다. [IFRS Digital Financial Reporting](https://www.ifrs.org/digital-financial-reporting/), [IFRS Taxonomy Regulators Guide](https://www.ifrs.org/content/dam/ifrs/standards/taxonomy/general-resources/ifrs-taxonomy-regulators-guide.pdf?la=en).

## 5. 역사적 분석기간 결정

### 5.1 고정 분기 수를 사용하지 않는 이유

IAS 1의 전기 비교정보는 외부 재무보고의 최소 표시 요구이지 valuation model의 최적 역사적 기간이 아니다. CFA는 forecast horizon과 접근법을 투자 목적, 산업 cyclicality, 기업 특성, 정보의 신뢰성·가용성에 맞추도록 한다. 따라서 “과거 몇 분기 이상”을 보편 품질선으로 두지 않는다.

### 5.2 기간 선택 절차

1. **분석 목적:** 모멘텀, 정상수익력, 경기순환, 자본구조 등 무엇을 추정할지 선언한다.
2. **현재 사업모델:** 현재 segment·수익모델과 경제적으로 비교 가능한 시작점을 찾는다.
3. **계절성:** 사용한 기간이 중요한 계절 패턴을 식별·검증할 수 있는지 확인한다.
4. **경기순환:** cyclical 기업이면 가능한 범위에서 최근 완전한 business cycle을 포함한다. CFA는 cyclical earnings 정상화에 완전한 cycle 정보를 고려한다. [CFA Market-Based Valuation](https://www.cfainstitute.org/insights/professional-learning/refresher-readings/2026/market-based-valuation-price-enterprise-value-multiples).
5. **구조적 단절:** 회계정책·segment·결산월·M&A·분할·중단영업·IPO를 structural-break flag로 표시한다.
6. **가용성:** 사용 가능한 전체 비교가능 기간, 결측, 정정, mapping confidence를 공개한다.
7. **window sensitivity:** 합리적인 대체 시작점에서 결론이 달라지는지 확인한다.

기간이 짧다는 이유만으로 억지로 비교 불가능한 데이터를 붙이지 않는다. 짧은 history가 결론을 제한하면 그 한계와 보완자료를 명시한다.

## 6. 모델 구조

### 6.1 논리적 layer

ICAEW가 권고하는 input–process–output의 명확한 흐름을 다음 layer로 구현한다. 명칭과 파일 번호는 구현 convention이며 품질의 외부 기준이 아니다.

```text
Purpose & Control
Sources & Raw Data
Mapping & Normalization
Operating Drivers & Assumptions
Supporting Schedules
Linked Financial Statements
Valuation & Scenarios
Outputs
Checks, Change Log & Limitations
```

대량 원천데이터와 반복 정제가 spreadsheet에 부적합하면 데이터베이스·query 도구에서 통제된 테이블을 만든 뒤 모델에 공급한다. ICAEW는 도구 적합성, 원천 정제, 일관된 구조를 먼저 판단하도록 권고한다.

### 6.2 연결 원칙

CFA Financial Modeling의 구조에 따라 material한 항목은 다음 관계로 연결한다.

```text
Operating assumptions
  → revenue / cost / working-capital / PP&E / tax / debt / equity schedules
  → income statement / balance sheet / cash-flow statement
  → free cash flow / valuation / decision outputs
```

`3-statement model`은 분석 핵심 세 표가 연결된다는 뜻이며, IAS 1상 완전한 재무제표 전체와 동일하다고 표현하지 않는다. IAS 1상 complete set에는 자본변동표와 주석 등도 포함된다.

### 6.3 spreadsheet controls

- 변경 가능한 input은 공식 안에 숨기지 않고 별도 assumption cell에서 참조한다.
- 입력, 공식, 출력, check를 색상뿐 아니라 style·validation·protection으로 구분한다.
- 동일한 계산을 여러 곳에서 반복하지 않고 단일 결과를 참조한다.
- 복잡한 계산은 검토 가능한 단계로 나눈다.
- 원천 데이터는 수동수정하지 않고 변환 layer에서 mapping한다.
- version, owner, as-of date, intended use, prohibited use를 workbook에 표시한다.
- change history와 이전 버전 식별정보를 보존한다.

근거: [ICAEW Twenty Principles](https://www.icaew.com/technical/technology/excel-community/20-principles-for-good-spreadsheet-practice-2024-edition).

### 6.4 accounting·formula checks

- `Assets = Liabilities + Equity`
- 현금흐름표 기말현금과 재무상태표 현금의 reconciliation
- retained earnings, debt, PP&E 등 material roll-forward
- segment 합계와 연결 총액의 reconciliation
- 누적 flow와 개별기간 flow의 reconciliation
- 연결·별도, 통화·단위, 기간 혼입 탐지
- source/assumption에서 output까지 lineage 완결성
- 미검토 XBRL mapping과 최신 정정공시 여부
- spreadsheet error value 탐지
- 극단·불가능 input에서의 동작
- 핵심 계산의 독립 재계산

수학적 identity는 원칙적으로 일치해야 한다. 표시단위 반올림 때문에 tolerance가 필요하면 source unit, 반올림 방식, 영향의 materiality에서 계산해 문서화한다. 특정 원화·비율 tolerance를 외부 기준처럼 고정하지 않는다. 근거: [IAS 7](https://www.ifrs.org/issued-standards/list-of-standards/ias-7-statement-of-cash-flows/), [ICAEW Twenty Principles](https://www.icaew.com/technical/technology/excel-community/20-principles-for-good-spreadsheet-practice-2024-edition).

## 7. Driver-based forecast

### 7.1 forecast object 선택

CFA가 제시하는 forecast object는 operating driver, 개별 재무 line, summary measure, ad hoc object다. 다음 기준으로 대상회사에 맞는 object를 선택한다.

- 정보 가용성과 신뢰성
- 효율과 유지 가능성
- 설명력
- 실제 결과로 검증할 수 있는지
- 사업모델·산업구조·경기민감도와의 적합성

공개 driver가 없으면 숫자를 발명하지 않는다. 공개 재무 line이나 aggregate margin으로 예측하고 정보 제한을 명시한다.

### 7.2 revenue·cost·investment 연결

- Revenue: 회사 특성에 따라 top-down 또는 bottom-up 방식을 사용한다.
- 가능한 bottom-up object: volume × price, 제품·지역·segment, capacity, customer 또는 공식 KPI.
- material한 경우 독립적인 다른 접근으로 revenue를 cross-check한다.
- Opex: 공개 상세가 부족하면 aggregate object를 사용할 수 있으나 revenue와 일관되어야 한다.
- Working capital: 매출·비용과 회전율·days 등 설명 가능한 관계로 연결한다.
- Capex: maintenance와 growth purpose를 구분하고 strategy·capacity·revenue와 연결한다.
- Capital structure: 역사적 leverage, 재무전략, 투자계획과 일관되게 둔다.

근거: [CFA Company Analysis: Forecasting](https://www.cfainstitute.org/insights/professional-learning/refresher-readings/2026/company-analysis-forecasting).

### 7.3 산업 driver library는 후보일 뿐이다

다음 식은 대상회사가 관련 KPI를 공식적으로 공개하고 경제적 관계가 성립할 때만 사용한다.

#### 결제·핀테크 예시

```text
Revenue ≈ payment volume × effective take rate + other service revenue
```

거래액, 건수, merchant mix, 결제수단, take rate, 결제원가, 정산주기, credit/fraud cost 등은 회사의 공시 정의와 accounting scope가 확인될 때만 사용한다.

#### AI·software 예시

```text
Revenue ≈ subscription/license + usage/project + maintenance
```

ARR, 고객, ARPA, backlog, project conversion, inference/cloud cost 등은 공식 공개 범위만 사용한다.

#### 소비재 예시

```text
Revenue ≈ volume × realized price
또는 segment/geography/channel revenue의 합
```

국가·채널·브랜드, volume, ASP, inventory, marketing, platform fee, FX는 공식 분해와 정의가 있을 때 사용한다.

### 7.4 explicit forecast horizon

고정 분기·연도 수를 사용하지 않는다. 다음을 함께 만족하는 마지막 명시기간을 정한다.

- 분석이 지원하는 투자·전략 의사결정 horizon과 맞는다.
- 산업 cyclicality와 회사의 성장·경쟁우위 전환을 포착한다.
- growth, margin, reinvestment, working capital, risk·capital structure가 장기적으로 지속 가능한 상태로 이동한다.
- 더 먼 기간의 세부 예측이 정보의 신뢰성·검증가능성을 높이지 않는 지점에서 세분화를 멈춘다.

고성장기간은 회사 규모, 잠재시장, excess return과 진입장벽·경쟁우위 지속성으로 판단할 수 있다. 이는 보조 판단근거이며 고정 연수를 뜻하지 않는다. [Damodaran — How long will high growth last?](https://pages.stern.nyu.edu/adamodar/New_Home_Page/valquestions/highgrowthperiod.htm).

### 7.5 scenario와 thesis-break

- 단일 예측보다 material risk를 반영할 필요가 있으면 복수의 coherent scenario를 만든다.
- scenario 수는 중요한 경제적 경로의 수에서 결정하며 미리 고정하지 않는다.
- 각 scenario는 일부 숫자를 임의로 가감하는 표가 아니라 driver, 재무제표, 자금조달, valuation이 내부 일관된 경로다.
- 확률을 부여할 경우 역사적 base rate, market evidence 또는 명시적 판단근거와 기준일을 기록한다.
- thesis-breaking condition은 결론을 실제로 바꾸는 driver threshold 또는 사건으로 정하고 model에서 역산한다.
- monitoring date는 실제 공시 일정, 규제 일정, 계약·제품 milestone에 연결한다. 관행적 월수로 고정하지 않는다.

근거: [CFA Company Analysis: Forecasting](https://www.cfainstitute.org/insights/professional-learning/refresher-readings/2026/company-analysis-forecasting), [CFA Standard V(A)](https://www.cfainstitute.org/standards/professionals/code-ethics-standards/standards-of-practice-v-a).

## 8. 검증·backtest·monitoring

### 8.1 적용 원칙

SR 26-2는 validation의 성격·강도가 모델 목적, 방법론, 사용, materiality, 데이터 제약에 맞아야 한다고 한다. P1은 이를 규제 준수가 아닌 비례적 품질 원칙으로 참조한다.

### 8.2 out-of-time 검증

1. forecast origin마다 그 시점에 이용 가능했던 `as_reported` vintage만 사용한다.
2. 목적과 데이터 빈도에 맞는 예측 horizon별로 실제값과 비교한다.
3. 가능하면 rolling-origin 방식으로 사용 가능한 독립 origin을 활용한다.
4. 표본 수, 구조적 regime, 정정공시, contaminated event를 함께 보고한다.
5. 기간 선택을 바꾸면 결론이 얼마나 달라지는지 확인한다.

고정된 backtest 분기 수나 횟수를 통과조건으로 두지 않는다. SR 26-2는 outcome analysis가 backtesting·outlier analysis 등 여러 형태를 취할 수 있고 선택은 목적·방법·데이터 가용성에 달린다고 명시한다. Rolling-origin의 원리에는 [Tashman (2000)](https://doi.org/10.1016/S0169-2070(00)00065-0)을 참고한다.

### 8.3 benchmark 선택

모델 목적에 맞는 naive 또는 대체모형을 **사전에** 문서화한다. 후보는 다음과 같으며 전부를 기계적으로 사용할 필요는 없다.

- 전기 유지
- 전년동기 또는 seasonal-naive
- 단순 성장·margin base-rate
- 다른 독립 forecast object
- 공개 시점에 실제 이용 가능했던 비교 가능한 consensus

어떤 benchmark를 선택·제외했는지와 경제적 이유를 남긴다. 평균오차 하나만으로 승인하지 않고 horizon별 성능과 의사결정 영향을 본다.

### 8.4 metric 선택

| 지표 | 사용 원칙 |
|---|---|
| MAE | 같은 단위·규모에서 원 단위 오류를 설명할 때 사용; 서로 다른 회사·계정의 raw MAE를 직접 비교하지 않음 |
| MAPE | actual이 0이거나 0에 가깝거나 부호가 바뀌는 순이익·EPS·FCF에는 주지표로 쓰지 않음 |
| MASE | naive forecast error로 scale을 조정해 series 간 비교가 필요할 때 사용; seasonal period와 denominator, 상수계열 예외를 명시 |
| Bias | 지속적 과대·과소예측 여부를 점검 |
| Decision impact | forecast error가 valuation·추천·자금판단을 바꿨는지 측정 |

`MASE < 1`은 정의한 naive benchmark보다 나았다는 뜻이지 보편적 승인선이 아니다. 지표 한계를 근거로 한 자세한 논의는 [Hyndman & Koehler (2006)](https://doi.org/10.1016/j.ijforecast.2006.03.001)을 따른다.

### 8.5 검증 결론

고정 오차율 대신 다음 증거를 함께 본다.

- 사전 정의된 benchmark 대비 성능과 horizon별 안정성
- 표본 수와 오차분포의 불확실성
- 오류의 재무적 materiality와 decision impact
- 지속적·반복적 bias 또는 deterioration
- 데이터·방법·사용범위 변경
- sensitivity·stress에서의 안정성과 사용 경계
- 알려진 한계와 보완통제

결론 상태는 `사용 가능`, `사용범위 제한`, `재보정·개선 필요`, `사용 불가`처럼 행동과 연결한다. 표본이 짧으면 숫자형 합격을 선언하지 않고 검증 제한과 강화 monitoring을 명시한다.

### 8.6 monitoring·revalidation trigger

검토 주기를 임의의 달력 횟수로 고정하지 않는다.

- 최초 사용 전 validation
- 새 actual 또는 중요 정정공시 공개 시 outcome monitoring
- 방법론, data source, schema, 목적, horizon의 material change
- 지속적 성능악화 또는 반복 override
- 사업모델·회계·시장 regime의 structural change
- 외부 vendor/model update

근거: [Federal Reserve SR 26-2](https://www.federalreserve.gov/frrs/guidance/supervisory-guidance-on-model-risk-management.htm).

## 9. valuation method 선택

### 9.1 방법을 의무화하지 않는다

DCF와 trading comps를 무조건 모두 수행하거나 고정 가중하지 않는다. 회사 특성, 데이터 가용성·품질, valuation 목적·관점에 적합한 방법을 선택하고 제외 이유를 적는다. 여러 적합한 방법의 결과가 다르면 기계적으로 평균하지 않고 차이의 원인과 각 방법의 신뢰도를 설명한다. 근거: [CFA Equity Valuation: Applications and Processes](https://www.cfainstitute.org/insights/professional-learning/refresher-readings/2026/equity-valuation-applications-and-processes).

### 9.2 DCF를 사용할 때

- cash-flow definition과 discount rate를 일치시킨다: FCFF–WACC, FCFE–cost of equity.
- revenue, profitability, investment, financing이 연결된 forecast에서 FCF를 도출한다.
- operating asset과 non-operating asset, debt-like와 equity claim을 명시적으로 reconcile한다.
- single·multi-stage 구조는 회사 특성과 정상화 경로에 맞춰 선택한다.
- terminal year에 sustainable growth, margin/return, reinvestment, risk·capital structure가 일관되게 성립해야 한다.
- perpetual-growth 방식은 `discount rate > g`, 통화·nominal/real 기준 일치, 장기 경제성장과의 일관성을 확인한다.
- exit multiple을 쓰면 terminal-date fundamentals와 peer set 적합성, market-based terminal이라는 성격을 명시한다.
- terminal value 비중은 민감도·위험 신호로 공개하되 보편적 pass/fail 비율을 두지 않는다.

근거: [CFA Free Cash Flow Valuation](https://www.cfainstitute.org/insights/professional-learning/refresher-readings/2026/free-cash-flow-valuation), [CFA Discounted Dividend Valuation](https://www.cfainstitute.org/insights/professional-learning/refresher-readings/2026/discounted-dividend-valuation).

### 9.3 comparable company를 사용할 때

peer 수를 미리 정하지 않는다. 후보 universe에서 다음 경제적·회계적 비교가능성을 충족하는 기업을 포함하고 모든 중요한 제외 사유를 기록한다.

- 제품·수익모델·고객군
- 지역·규제·통화
- 성장·수익성·위험
- capital structure·reinvestment·capital intensity
- 연결범위·회계정책·기간
- 구조적 변화·일회성 왜곡
- 공시 품질과 시장가격의 신뢰성

모든 materially comparable 기업을 포함한다. 가까운 peer가 적으면 억지로 수를 채우지 않고 범위의 한계를 밝힌다. 표본이 허용하면 개별 multiple, range, 중앙경향, leave-one-out 결과를 보여 특정 기업 하나가 결론을 지배하는지 확인한다.

multiple은 numerator와 denominator의 claim을 맞추고, 음수·변동성·경기순환 denominator와 회계차이를 정상화하거나 한계를 공개한다. 근거: [CFA Market-Based Valuation](https://www.cfainstitute.org/insights/professional-learning/refresher-readings/2026/market-based-valuation-price-enterprise-value-multiples), [CFA peer research](https://rpc.cfainstitute.org/research/financial-analysts-journal/2017/stick-to-the-fundamentals-and-discover-your-peers).

### 9.4 sensitivity와 stress

- valuation과 decision에 material한 input을 먼저 식별한다.
- 범위는 대상회사의 역사적 변동, 공식 guidance, market evidence, 공식 stress scenario, break-even·thesis-break 값에서 도출한다.
- 개별 input과 중요한 공동변화를 모두 시험한다.
- 극단적이지만 가능한 조건에서 비선형성, liquidity, financing need, 모델 사용경계를 확인한다.
- 범위와 step의 source, as-of date, 선택 이유를 assumption log에 남긴다.

일률적인 퍼센트 폭, WACC step, sensitivity 표 크기, 최소 표 개수를 두지 않는다. 근거: [CFA Standard V(A)](https://www.cfainstitute.org/standards/professionals/code-ethics-standards/standards-of-practice-v-a), [CFA Equity Valuation: Applications and Processes](https://www.cfainstitute.org/insights/professional-learning/refresher-readings/2026/equity-valuation-applications-and-processes).

## 10. Investment/CEO Memo

### 10.1 분량이 아닌 충분성

CFA는 보편적인 industry-standard report format이 없다고 설명한다. 따라서 페이지·슬라이드·논점 개수를 고정하지 않는다. 문서는 명료하고 객관적이어야 하며, 핵심 가정을 밝히고, 사실과 의견을 구분하고, 분석–forecast–valuation–recommendation이 일관되고, 독자가 valuation을 비판할 충분한 정보와 위험·conflict를 포함해야 한다. 근거: [CFA Equity Research Report Essentials](https://www.cfainstitute.org/sites/default/files/-/media/documents/support/research-challenge/challenge/rc-equity-research-report-essentials.pdf), [CFA Equity Valuation: Applications and Processes](https://www.cfainstitute.org/insights/professional-learning/refresher-readings/2026/equity-valuation-applications-and-processes).

### 10.2 필수 내용

- as-of date, 회사·ticker·거래소, valuation basis
- 의사결정 질문과 조건부 결론
- business economics와 material revenue·cost·cash drivers
- 산업구조·경쟁위치와 peer logic
- 역사적 재무·earnings quality·구조적 단절
- forecast 방법, horizon, key assumptions와 근거
- valuation 방법 선택·제외 이유와 결과 reconciliation
- material scenario·sensitivity·thesis-break condition
- 가장 강한 반대논리와 operational·financial·regulatory risk
- 실제 확인할 공시·milestone과 monitoring trigger
- sources, facts/opinions, limitations, conflicts, 개인 프로젝트 disclaimer

### 10.3 CEO/Chief of Staff 변형

투자 recommendation을 다음 의사결정으로 변환할 수 있다.

- build, buy, partner 중 무엇이 공개 근거상 우월한가?
- 어떤 고객·채널·제품에 자원을 우선 배분해야 하는가?
- 어떤 KPI가 결과보다 먼저 움직이며 공식적으로 측정 가능한가?
- 어떤 break-even 또는 downside 조건에서 확대·중단·재설계해야 하는가?

질문은 분석대상의 공개자료와 관련 직무에서 반복되는 공식 decision pattern에서 도출한다. 정규직 전환을 전제로 한 장기 조직경력 서사는 사용하지 않고, 제한된 RA/CEO Staff 기간에도 남길 수 있는 재사용 가능한 분석자산·decision process를 강조한다.

### 10.4 제출형식

- 빠른 검토용: 한 줄 decision, 핵심 chart, 가장 중요한 risk와 source
- 본문: 위 필수 내용을 빠짐없이 담은 decision memo
- 검증용: model, source/evidence ledger, checks, assumptions, limitations, change log

형식별 분량은 독자가 결론을 이해하고 비판하는 데 필요한 정보로 결정한다.

## 11. 실행계획: 달력이 아닌 dependency gate

### Phase A — 목적·대상·as-of date

- 관련 직무의 공식 역할·방법론 reference와 금융 의사결정 요구를 evidence table에 기록한다.
- 후보기업에 선정 gate를 적용한다.
- decision question, intended/prohibited use, as-of date를 고정한다.
- 원천 수집·정규화 pilot으로 병목을 측정한다.

**완료 gate:** 대상 선택과 제외 이유가 금융 의사결정 가치·공개자료 적합성·프로젝트 목적에 연결되고, 일정 산정에 쓸 실제 pilot 근거가 있다.

### Phase B — sourcebook·normalization

- 공시 원문, XBRL, 시장자료, IR을 수집하고 hash·접수번호를 보존한다.
- `as_reported`와 `latest_restated` series를 분리한다.
- 연결·별도, 기간, 통화, 단위, taxonomy를 정규화한다.
- structural break와 mapping confidence를 기록한다.

**완료 gate:** material output이 원천까지 추적되고 정정·기간·범위 혼입 check가 통과한다.

### Phase C — business model·forecast

- 산업 가치사슬과 회사 economics를 공식 자료로 설명한다.
- material forecast object와 driver tree를 선택한다.
- supporting schedules와 재무제표를 연결한다.
- explicit horizon과 scenario를 company-specific evidence로 결정한다.

**완료 gate:** 가정이 재무결과에 연결되고 accounting·roll-forward checks가 통과하며, driver가 없는 곳의 한계가 공개된다.

### Phase D — valuation·validation

- 적용 가능한 valuation method와 제외 method를 판단한다.
- peer logic 또는 DCF transition을 검증한다.
- out-of-time outcome analysis와 사전 선택 benchmark를 수행한다.
- material sensitivity·stress와 thesis-break를 시험한다.

**완료 gate:** 모델 신뢰도와 한계, 상대적 성능, decision impact가 기록되고 사용범위가 정해진다.

### Phase E — communication·review·release

- Investment/CEO memo와 검증 부록을 작성한다.
- 사실·의견·가정·추천을 구분한다.
- 개발자와 이해관계가 가능한 한 분리된 reviewer가 formula, source, logic을 비판적으로 검토한다.
- 발견사항을 수정하거나 limitation·use restriction으로 남긴다.
- 읽기전용 snapshot과 version/change record를 보존한다.

**완료 gate:** 아래 release gate가 모두 통과한다.

### 일정 산정 방식

고정 주수는 두지 않는다. Phase A pilot 뒤 다음 항목으로 남은 작업량을 계산한다.

- 수집할 실제 문서·period·segment 수
- manual mapping이 필요한 extension·structural break
- model schedules와 valuation method의 복잡성
- validation origin과 reviewer 가용성
- 지원 마감일과 생략 가능한 선택 산출물

마감이 촉박하면 scope를 줄이되 source lineage, accounting checks, material downside, limitations는 생략하지 않는다. 선택 산출물을 줄이는 것이 핵심 통제를 줄이는 것보다 우선이다.

## 12. 비보상적 release gate

단일 점수와 합격점을 사용하지 않는다. 다음 중 하나라도 실패하면 공개하지 않는다.

### Gate R1 — 공식 원천·freshness

- 핵심 사실과 숫자에 공식 source, 접수번호/URL, 기준일, 기간이 있다.
- 최신 정정공시 적용 여부와 과거 vintage가 구분된다.
- 2차 자료나 AI 출력이 최종 숫자의 유일한 근거가 아니다.

### Gate R2 — accounting comparability

- 연결·별도, 분기·YTD, 통화·단위가 혼입되지 않았다.
- restatement·reclassification·structural break 처리가 설명된다.
- material mapping이 검토되었다.

### Gate R3 — formula integrity

- statements, cash, roll-forward, segment, source lineage checks가 통과한다.
- hardcode·formula·output이 구분되고 변경 가능한 값이 공식에 숨지 않는다.
- 남은 차이는 source rounding과 materiality로 설명된다.

### Gate R4 — reasonable basis

- forecast object, horizon, scenario, valuation method, peer 포함·제외에 근거가 있다.
- analysis–forecast–valuation–recommendation이 내부 일관된다.
- 중요한 반대논리, downside, limitation, use restriction이 공개된다.

### Gate R5 — validation

- look-ahead 없는 outcome analysis와 목적에 맞는 benchmark가 있다.
- metric 선택과 표본 한계가 설명된다.
- material sensitivity·stress와 decision impact가 확인된다.

### Gate R6 — effective challenge·reproducibility

- 모델 중요도·복잡성에 비례한 객관적 review가 수행되었다.
- review finding과 response·exception이 기록되었다.
- 다른 사람이 source → transform → assumption → output 경로를 추적할 수 있다.

독립 review의 필요·강도는 횟수가 아니라 risk와 review의 효과로 판단한다. 근거: [ICAEW Twenty Principles](https://www.icaew.com/technical/technology/excel-community/20-principles-for-good-spreadsheet-practice-2024-edition), [Federal Reserve SR 26-2](https://www.federalreserve.gov/frrs/guidance/supervisory-guidance-on-model-risk-management.htm).

## 13. 산출물 구조

### 13.1 필수 산출물

- `README`: 목적, 독자, as-of date, intended/prohibited use, 실행법
- source/evidence ledger: 원천·접수번호·기간·위치·한계
- raw snapshot과 hash: 당시 데이터 vintage 재현
- mapping·normalization log: 계정·기간·범위 변환
- operating model과 linked statements
- 적용 가능한 valuation 및 제외 이유
- validation·benchmark·sensitivity·limitations report
- Investment/CEO decision memo
- assumption log, decision log, review log, change log
- 읽기전용 model/report snapshot

### 13.2 선택 산출물

- 영문 executive summary
- 심층 appendix 또는 deck
- 자동화된 data pipeline
- 직무별 변형 memo
- 공개 가능한 sample dataset

선택 산출물은 지원 직무의 공식 요구 또는 전달효과가 확인될 때 추가한다. 장수·페이지 수는 품질 기준이 아니다.

### 13.3 logical folder mapping

다음은 ICAEW의 input–process–output·control 원칙을 파일에 구현하는 예시다. 이름 자체는 외부 표준이 아니므로 기존 작업환경에 맞게 바꿀 수 있다.

## 14. 관련 직무별 변형 규칙

회사 이름별 고정 부록을 먼저 만들지 않는다. 완성된 공통 모델에서 **관련 직무의 반복 의사결정 → 검증 가능한 deliverable evidence** mapping으로 view를 결정하고, 특정 지원 시에는 해당 공고와 실제로 겹치는 산출물만 사후 선택한다.

| 관련 직무가 확인하는 것 | P1 변형 |
|---|---|
| CEO 의사결정·시장/경쟁 분석 | decision memo, driver tree, counterargument, monitoring trigger |
| CorpDev·투자·M&A | build–buy–partner, target logic, transaction rationale, integration/downside |
| FP&A·사업관리 | segment/channel P&L, budget/actual logic, rolling forecast, cash sensitivity |
| RA·리서치 | sourcebook, industry map, earnings/valuation, catalyst·risk·thesis-break |
| AI·software strategy | 공개 가능한 revenue model, backlog/conversion, compute/R&D economics |
| 금융권 research | earnings quality, forecast, valuation, risk, model validation |

어떤 변형도 미공개 지표를 사실처럼 채우지 않는다. 지원회사가 비상장사이면 공개 상장사 분석에서 얻은 방법을 이전 가능한 skill로 제시하고, 지원회사 자체의 숫자를 추정해 붙이지 않는다.

## 15. 이력서·면접 표현

완료 전에는 분기 수, 전망 연수, peer 수, 오차 성과를 약속하지 않는다. 실제 수행 후 verified scope만 채운다.

### 이력서 템플릿

> 공개 공시·시장자료의 vintage와 정정 이력을 보존해 `[대상기업/산업]`의 driver-based linked financial model을 구축하고, `[적용한 valuation 방법]`·out-of-time benchmark·material sensitivity를 통해 `[의사결정 질문]`에 대한 조건부 memo를 작성함.

### 면접 구조

- 왜 이 대상과 decision question을 골랐는가
- 어떤 공식 source와 비교가능성 문제를 해결했는가
- 어떤 driver가 재무결과를 실제로 설명했는가
- forecast horizon과 valuation method를 왜 그렇게 정했는가
- benchmark 대비 무엇이 개선되거나 실패했는가
- 가장 강한 반대논리와 결론을 바꾸는 조건은 무엇인가
- 지원 직무에서 이 process를 어떻게 재사용할 것인가

### 피해야 할 표현

- “정확한 목표주가를 산출했다.”
- “AI가 기업가치를 예측했다.”
- “실제 경영진 의사결정을 지원했다.”
- “비공개 단위경제를 알아냈다.”
- “SR 26-2를 준수했다.”

대신 `공개정보 기준으로 분석했다`, `조건부 시나리오를 모델링했다`, `당시 데이터로 검증했다`, `한계와 사용범위를 명시했다`고 표현한다.

## 16. 첫 실행 체크리스트

- [ ] 관련 직무의 공식 역할·방법론 URL·접근일·핵심 분석 절차를 기록한다.
- [ ] 후보기업별 Gate A–E evidence table을 작성한다.
- [ ] 선택한 후보의 공시 한 기간을 raw → mapping → normalized까지 pilot한다.
- [ ] 정정공시, 연결·별도, 기간값·누적값, taxonomy extension을 확인한다.
- [ ] 실제 pilot 처리량과 structural break로 일정·scope를 산정한다.
- [ ] 분석 목적과 역사적·전망 horizon 결정근거를 decision log에 남긴다.
- [ ] driver가 공개되지 않은 항목의 대체 forecast object와 한계를 정한다.
- [ ] valuation 방법 후보와 제외 이유를 적는다.
- [ ] backtest vintage, origin, benchmark, metric을 model build 전에 선언한다.
- [ ] release gate reviewer와 review 범위를 model materiality에 맞게 정한다.

첫날의 목표는 특정 회사에 대한 결론을 서둘러 만드는 것이 아니다. **공식 근거로 끝까지 재현 가능한 대상과 분석 범위를 확정하는 것**이다.
