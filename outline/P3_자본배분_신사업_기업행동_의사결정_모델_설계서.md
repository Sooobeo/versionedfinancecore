## 0. 설계 원칙

### 0.1 사용자 전제

이 프로젝트는 특정 지원기업의 면접 과제를 모사하거나 현재 열린 채용공고에 맞추는 프로젝트가 아니다. CEO Staff·전략·CorpDev·Corporate Finance·FP&A·CVC·금융 RA에서 반복되는 자본배분 판단을 금융적으로 증명하는 개인 포트폴리오다.

FinDone은 본인이 쓰려고 만든 제품이다. P3에서 FinDone의 사용자 성장·retention을 억지로 증명하지 않는다. FinDone은 금융지식 구조화, 제품 구현, AI 활용과 품질 gate의 기존 증거로만 연결한다.

정규직 전환을 전제로 하지 않는다. 제한된 CEO Staff·RA 기간에도 독립적으로 검토·인수인계·재사용할 수 있는 decision asset을 남기는 방식으로 설계한다.

[USER] P3의 core 데이터는 분석대상 회사의 임직원·계약자·거래상대방·감독기관만 볼 수 있는 자료를 사용하지 않는다. 개인 또는 민간 법인이 고용·자문·NDA 관계 없이 합법적으로 취득할 수 있는 자료만 사용한다.

- core는 무료 공식자료와 회사 공개자료만으로 끝까지 재현한다.
- 상용 데이터는 이용허락과 파생결과 공개범위를 확인한 선택 cross-check로만 사용한다.
- 합성자료는 계산·통제 test fixture일 뿐 실제 기업·거래의 사실, actual 또는 truth set이 아니다.
- 공개자료 기반 analyst simulation이며 실제 회사의 투자위원회·이사회·경영진 의사결정 지원으로 표현하지 않는다.
- 공개되지 않은 internal budget, pipeline, bid, data room, integration plan, risk appetite 또는 실제 owner를 안다고 표현하지 않는다.

P1·P2와의 역할도 분리한다.

- P1: 공개기업의 사업 driver, 통합 재무전망, 가치평가와 투자/CEO memo
- P2: 공개자료 기반 plan·forecast·actual 의미 분리, variance, reforecast와 action loop
- P3: 필요하면 P1·P2의 검증된 기업·산업 데이터 자산을 재사용하되 독립 case도 허용하고, 대안별 증분 세후현금흐름, 거래·자금조달·pro forma, 실행위험과 조건부 자본배분 판단을 추가

### 0.2 제거한 임의 기준

다음 숫자나 방법은 보편적인 공식 합격기준이 아니다. P3의 근거 없는 default로 사용하지 않는다.

| 제거한 임의 기준 | P3의 결정 원리 |
|---|---|
| 특정 지원회사·산업·거래유형을 자동 선택 | 직무 관련성, 공개자료의 완전성, 대안 비교 가능성, 검증 가능성 gate로 case 선택 |
| 옵션·타깃·peer·선행거래·scenario 개수 고정 | 실제로 실행 가능하고 의사결정을 바꾸며 공개근거가 있는 항목만 유지 |
| 모든 case에 build·buy·partner·divest를 강제 | mutually exclusive·compatible·dependent 관계를 정의하고 가능한 대안만 비교 |
| 고정 capital budget·hurdle rate·IRR·payback | 공개 가능한 자금제약, 위험, 비용자본과 break-even에서 case별 결정 |
| WACC spread·control premium·minority discount 고정 | 시장·기업·거래 조건과 평가목적에 맞는 근거·범위·변경조건을 기록 |
| DCF·comps·precedent·accretion을 항상 모두 사용 | 목적과 자료가 맞는 방법만 사용하고 부적합한 방법의 제외 이유를 기록 |
| 여러 가치평가 결과의 기계적 평균 | 경제적 의미, 입력 신뢰성과 적용범위를 비교해 판단 |
| synergy·integration cost·success probability 고정 | 공개근거 또는 명시된 analyst scenario로만 두고 break-even을 병기 |
| 고정 terminal growth·exit multiple | 정상상태, 산업구조, 재투자와 자본수익률 논리에 연결 |
| 고정 forecast horizon·event window·sensitivity 폭 | cash-flow duration, 실행 lead time, 공개자료의 신뢰성, 역사분포와 thesis-break에서 도출 |
| EPS accretion 또는 발표 직후 주가상승을 성공으로 간주 | 현금흐름 가치, 대가, 위험, 자금조달과 사후 공개성과를 함께 검토 |
| 공개되지 않은 TAM 점유율·unit economics·cost allocation을 역산 | 공개 grain으로 범위를 낮추거나 assumption·limitation으로 분리 |
| 공개되지 않은 내부 승인·budget·covenant 여유를 fact로 표현 | 공식자료가 없으면 analyst scenario와 공개 한계를 표시 |
| 가중 scorecard와 합격점 | 중요한 gate 하나의 실패를 다른 장점으로 상쇄하지 않는 비보상적 gate 사용 |
| 프로젝트 주수·review 횟수·memo 페이지 수 고정 | data feasibility와 산출물 의존관계, 오판 위험에 비례해 결정 |

숫자가 필요하면 외부 표준처럼 쓰지 않는다. source, as-of date, 산출근거, analysis owner, sensitivity와 변경조건을 assumption/decision log에 남긴다.

### 0.3 판단 라벨과 주장 태그

중요한 설계 선택에는 다음 라벨을 붙인다.

| 라벨 | 의미 | 허용 근거 |

| [EVID] | case 증거 | 민간이 합법적으로 확보 가능한 공시·회사 IR·정부·거래소·licensed commercial 자료 |
| [USER] | 사용자 목적 | 관련 직무·금융 도메인·공개범위에 관한 사용자 제약 |
| [CALC] | 계산 | 허용 source와 명시된 convention에서 재현되는 산식 |
| [JUDG] | 전문판단 | 대안·근거·한계·반대근거·변경조건을 기록한 선택 |

모델과 memo의 개별 주장에는 다음 태그를 사용한다.

| 태그 | 의미 | 예 |
|---|---|---|
| [F] Fact | 원천자료에 직접 존재 | 공시된 인수대가, 발표일, 공개 KPI |
| [D] Derived | 허용자료에서 재현 가능하게 계산 | implied premium, incremental NPV |
| [A] Assumption | 분석을 위해 둔 가정 | adoption ramp, synergy timing |
| [I] Inference | 사실·계산을 연결한 해석 | 공개증거가 지지하는 전략적 의미 |
| [R] Recommendation | 조건부 행동 제안 | 가격이 한도 이하일 때 buy |
| [M] Measured | 본 프로젝트 test에서 직접 측정 | formula test, 재현시간, 오류율 |

문서의 owner 표기는 다음으로 제한한다.

- analysis owner: 프로젝트 작성자
- reviewer: 독립적인 관점에서 모델과 판단을 challenge하는 검토자
- proposed accountable role: 공개 조직정보와 일반적인 직무범위에 근거한 제안 역할

분석대상 회사의 실제 내부 책임배정은 공식 공개자료로 확인되지 않는 한 [F]가 아니다.

### 1.2 적용상 주의

- CFA 자료는 분석 원칙과 역량 범위의 근거다. 특정 회사의 최적 대안, hurdle rate, premium, synergy, forecast horizon 또는 거래가격을 정하지 않는다.
- CFA Corporate Restructuring에 소개되는 size 관련 rule of thumb은 학습자료의 설명이다. P3의 자동 materiality cutoff로 가져오지 않고 결정 영향·현금노출·전략적 fit을 함께 본다.
- CFA Due Diligence는 assurance 또는 실사 표준이 아니라 교육용 Practical Skills Module이고, P3는 data room 접근권한이 없다. 따라서 결과물은 public-source preliminary diligence이지 full diligence가 아니다.
- IFRS는 historical financial reporting의 인식·측정·표시 기준이다. analyst의 신사업 경제성·시너지 전망을 보증하거나 특정 valuation method를 명령하지 않는다.
- 17 CFR § 210.11-02는 미국 등록인의 pro forma 공시 규정이다. 한국 기업 개인 프로젝트에 법적으로 적용된다고 주장하지 않고 historical·Transaction Accounting·해당 시 Autonomous Entity·선택적 Management’s Adjustments와 forward-looking analyst forecast를 분리하는 참고구조로 사용한다. SEC Financial Reporting Manual은 staff guidance이고 그 자체가 권위규정은 아니므로 보조 확인용으로만 쓴다.
- Green Book과 Magenta Book은 영국 중앙정부의 공공사업 appraisal·evaluation 지침이며 기업가치평가 기준이 아니다. P3에는 business-as-usual, option comparison, switching value, uncertainty, counterfactual과 인과강도 표기의 유사 원칙만 가져오고 공공부문 할인율·사회적 가치 산식을 사용하지 않는다.
- IFRS Foundation 자료의 이용·재배포 조건을 확인한다. 표준 원문을 대량 복제하지 않고 적용한 원칙을 요약해 직접 링크한다.
- SR 26-2는 은행 감독지침이며 개인 프로젝트의 규제 준수 근거가 아니다. 위험기반 검증과 독립 challenge 원칙만 비례 적용한다.
- 아래의 file schema, gate, 대안 taxonomy와 계산 convention은 공식기관의 의무 형식이 아니라 위 원칙을 구현한 [JUDG] 설계다.

### 2.1 목적

P3는 다음 폐쇄루프를 공개자료만으로 재현한다.

~~~text
의사결정 질문·as-of date
→ 실행 가능한 대안과 status quo 정의
→ public-at-the-time evidence·제약
→ standalone·counterfactual
→ 대안별 incremental after-tax cash flow
→ transaction·financing·pro forma
→ NPV·capital efficiency·liquidity·downside·optionality
→ 조건부 recommendation·no-go·decision trigger
→ public outcome·monitoring·revalidation
~~~

분석의 목적은 가장 큰 TAM이나 가장 높은 IRR을 찾는 것이 아니다. 상호 비교 가능한 경제적 기준에서 자본을 투입·회수·보류하는 결정을 만들고, 결론이 틀릴 수 있는 조건과 공개정보의 한계를 보여주는 것이다.

### 2.2 핵심 질문

> 기준일 당시 민간이 확보할 수 있었던 공개정보만으로 볼 때, 현상 유지·연기·자체투자·제휴·소수지분투자·인수·매각·중단·자본회수 중 어떤 실행 가능한 대안이 가장 높은 위험조정가치를 만들며, 가격·수요·비용·timing·funding·규제 조건이 어떻게 바뀌면 결론이 뒤집히는가?

이 질문은 case에 맞춰 좁힌다.

이 문서에서 ‘실행 가능한 대안’은 공개정보상 중대한 법적·재무적·운영상 장애가 확인되지 않은 analyst-defined alternative를 뜻한다. 내부 capability·budget·mandate·협상의사와 비공개 승인조건까지 확인했다는 뜻이 아니며, 그 실제 조직 실행가능성은 PUBLICLY_NOT_OBSERVABLE 또는 INSUFFICIENT_PUBLIC_EVIDENCE로 남긴다.

- decision unit: 전사, segment, product line, 지역, asset 또는 공개된 거래대상
- intended user: CEO/board/IC를 모사한 analyst audience, 전략·CorpDev·FP&A·투자분석 reviewer
- decision date: 공개정보 cut-off가 되는 as-of date
- capital consequence: 투자액, 현금 trough, debt·equity·희석, 회수액 또는 포기한 대안
- success condition: 가치, 유동성, 전략적 제약과 실행가능성을 동시에 만족하는 조건

### 2.3 하지 않을 것

- 실제 회사의 승인되지 않은 투자안, bid, valuation 또는 내부 전략을 안다고 주장
- 내부 data room 없이 quality of earnings·법률·세무·운영 실사를 완료했다고 주장
- 공개되지 않은 target forecast, customer cohort, contract, employee, integration plan을 만들어 actual처럼 사용
- 합성 target이나 가상 transaction을 실제 기업의 사실로 표현
- 회사 guidance 또는 deal rationale를 analyst base case와 동일시
- 최신 정정자료·사후성과를 과거 decision date에 이미 알았던 것처럼 사용
- 발표 주가반응, EPS accretion, 매출성장 또는 goodwill impairment 하나만으로 가치창출·실패를 단정
- 상관관계를 기업행동의 인과효과로 과장
- 투자·회계·세무·법률 자문 또는 fairness opinion 제공

## 3. 민간 접근가능 데이터와 case 선정

### 3.1 민간 접근가능성의 정의

민간 접근가능은 분석대상 회사에 취업·파견·자문계약을 맺거나 거래상대방·감독기관 지위가 있어야만 볼 수 있는 자료가 아니라, 일반 개인 또는 법인이 동일하거나 공개된 조건으로 합법적으로 취득할 수 있다는 뜻이다.

| Access class | core 사용 | 조건 |
|---|---|---|
| PUBLIC_OFFICIAL | 허용 | DART·KIND·KRX·SEC·중앙은행·통계기관·법령·법원 등 공식 공개자료 |
| PUBLIC_COMPANY | 허용 | 회사 공시·IR·earnings release·공개 KPI·가격표·제품문서·거래 발표 |
| COMMERCIAL_LICENSED | 선택 | 민간 구매·구독 가능하고 분석·파생결과·재배포 범위를 license가 허용할 때 |
| PUBLIC_WEB | 보조 | 약관·robots·저작권·database right를 확인한 lawful collection이며 원문으로 재검증 가능할 때 |
| SYNTHETIC_TEST_ONLY | test 전용 | 계산·통제의 known-answer test이며 factual evidence·actual·truth set으로 사용 금지 |

P3 core는 PUBLIC_OFFICIAL과 PUBLIC_COMPANY만으로 완결한다. COMMERCIAL_LICENSED가 없어도 대안 비교와 핵심 결론이 재현되어야 한다.

### 3.2 제외자료

다음은 core와 optional 모두에서 제외한다.

- 내부 budget·board pack·investment committee memo·ERP·CRM·payroll·sales pipeline
- data room, CIM, management case, non-public bid, NDA·clean-team 자료
- target의 미공개 customer·contract·pricing·churn·cohort·employee 정보
- 내부 synergy estimate, integration workplan, separation plan, stand-alone cost allocation
- 감독기관·수사기관·신용정보집중기관만 접근 가능한 비공개 자료
- leak·무단공유·약관위반 scraping·access-control 우회
- 출처·취득권한·license를 설명할 수 없는 vendor export
- AI 답변·검색요약을 원천 확인 없이 actual로 사용한 자료

### 3.3 합성데이터의 제한된 역할

합성데이터는 다음 test에만 사용한다.

- incremental cash-flow identity와 sign convention
- purchase consideration·funding·share count·debt roll-forward
- pro forma balance, cash-flow와 EPS denominator
- synergy timing·integration-cost double-count 방지
- scenario·break-even·max-price solver
- missing·duplicate·restatement·currency·unit exception

규칙:

- 실제 회사의 미공개 값을 메우지 않는다.
- public actual·transaction fact와 namespace·화면·export를 물리적으로 분리한다.
- generator, seed, parameter, source basis, expected result와 목적을 공개한다.
- memo·README·snapshot에 SYNTHETIC_TEST_ONLY 표시를 유지한다.
- synthetic test 통과를 실제 거래의 타당성·성과로 표현하지 않는다.

### 3.4 공개데이터로 가능한 세 가지 실행 모드

#### Mode A — 현재 공개정보 기반 analyst alternative

현재 as-of date의 공개정보로 특정 기업·segment의 status quo와 실행 가능한 전략 대안을 모델링한다.

- 장점: 현재 직무와 직접 연결되는 recommendation·break-even을 만들 수 있다.
- 한계: 실제 내부 선택지·capability·budget·협상조건을 알 수 없다.
- 표기: analyst hypothetical case, not company proposal

#### Mode B — historical ex-ante reconstruction

과거 기업행동 발표 직전의 public-at-the-time 정보만 freeze하고 당시 독립 analyst가 내릴 수 있었던 판단을 재구성한다.

- 장점: hindsight를 통제하고 이후 actual과 비교할 수 있다.
- 한계: 당시 공개되지 않은 competing bid·diligence finding·management forecast는 복원할 수 없다.
- 표기: historical ex-ante analyst reconstruction

#### Mode C — announced/completed action outcome study

공개 발표·신고·closing·후속 공시가 충분한 acquisition·JV·divestiture·spin-off·capital action의 rationale, terms, pro forma와 공개 사후성과를 추적한다.

- 장점: transaction fact와 사후 공개지표가 있다.
- 한계: 관측되지 않은 counterfactual과 동시 발생한 거시·산업·경영 변화 때문에 인과를 단정할 수 없다.
- 표기: public-source outcome analysis, not causal proof

[JUDG] scope control의 기본은 한 mode로 source→model→decision 경로를 먼저 닫는 것이다. data feasibility pilot에서 여러 mode의 결합이 별도 검증가치를 만들고 빈티지·claim을 분리할 수 있음이 확인될 때만 복수 mode를 core로 둔다. mode 수 자체는 통과기준이 아니다.

### 3.5 금융 도메인 우선 case archetype

아래는 지원회사 목록이나 우선순위가 아니라 공개자료 feasibility 후보군이다.

| Archetype | 공개 source 후보 | 가능한 질문 | 핵심 한계 |
|---|---|---|---|
| 상장 결제·거래 플랫폼 | 공시·IR KPI·가격정책·결제통계·거래소 자료 | build/partner/buy, 국가·product 확장, processing 투자 | merchant·customer grain과 risk cost가 제한될 수 있음 |
| 상장 은행·소비자금융 | 재무·regulatory disclosure·금리·신용·자본 통계 | digital build, portfolio acquisition/divest, capital return·delever | 내부 PD/LGD·risk appetite·covenant를 발명하지 않음 |
| 상장 증권·자산운용 | 공시·AUM·flow·거래량·시장자료 | product/channel build, minority investment, buy, capital return | client·position·fee schedule 세부가 비공개일 수 있음 |
| 상장 보험·보증 | 공시·regulatory disclosure·금리·손해율·자본 공개자료 | distribution partnership, book acquisition/divest, capital action | 내부 actuarial model·reinsurance terms를 만들지 않음 |
| 금융 인프라·B2B software | 공시·공공조달·가격표·제품문서·공개 고객사례 | build vs partner vs buy, capacity·compliance investment | contract economics·retention이 제한될 수 있음 |
| 공개 거래문서가 충분한 비금융 case | 합병·매각 공시, proxy/registration statement, IR, post-close filing | transaction·pro forma·integration·outcome 분석 | 금융 도메인 신호는 financing·capital allocation에 한정될 수 있음 |

금융 archetype을 우선 검토하되 데이터가 부족하면 공시가 풍부한 기업행동 case를 선택한다. 금융회사 분석에서는 규제자본·유동성·고객보호 제약을 공개 범위에서 함께 본다.

### 3.6 비보상적 선정 gate

#### Gate A — 민간 접근가능성·license

- 모든 core source에 URL/provider, release date, access class와 이용조건이 있다.
- 고용·NDA·감독권한 없이 동일 조건으로 다시 확보할 수 있다.
- 무료 공식·회사 공개자료만으로 핵심 결론을 재현한다.
- 상용자료가 없어도 핵심 결론이 무너지지 않는다.

#### Gate B — as-of·historical vintage

- announcement, filing, vote/approval, close와 subsequent reporting date를 구분할 수 있다.
- historical mode이면 decision date에 공개됐던 정보집합을 복원할 수 있다.
- first-filed, amended/restated와 latest 값을 분리한다.
- hindsight 정보가 ex-ante model에 섞이지 않는다.

#### Gate C — 직무·금융 의사결정 관련성

- 특정 지원회사 없이도 capital allocation·strategy·CorpDev·finance 역량을 보여준다.
- output이 조건부 action, no-go 또는 monitoring trigger로 연결된다.
- 금융 도메인에서는 자금·위험·자본·유동성 효과를 설명할 수 있다.

#### Gate D — 대안·counterfactual 정의

- status quo와 실제로 구분되는 실행 가능한 대안이 있다.
- 대안의 상호배타·병행·선행·조건부 관계를 표시할 수 있다.
- 포함·제외 이유와 public evidence gap을 기록한다.
- do nothing과 defer를 같은 대안으로 취급하지 않는다.

#### Gate E — incremental cash flow·valuation 가능성

- revenue·cost·capex·working capital·tax·terminal/exit을 공개근거 또는 명시가정으로 연결한다.
- sunk cost, opportunity cost, cannibalization과 externality를 검토한다.
- project cash flow와 financing cash flow의 double count를 피할 수 있다.
- NPV·break-even 또는 다른 적합 지표를 재현할 수 있다.

#### Gate F — financing·liquidity·constraint 가능성

- 선택한 대안에 필요한 공개 cash·debt·maturity·share count·capital structure를 확보할 수 있고, transaction module을 활성화한 경우 transaction terms를 확보할 수 있다.
- funding, leverage, dilution, cash trough와 필요한 승인·규제 제약을 모델링하거나 limitation 처리할 수 있다.
- 공개되지 않은 내부 limit를 fact로 만들지 않는다.

#### Gate G — 검증·outcome 가능성

- 활성화한 module의 accounting·formula와 해당 시 pro forma reconciliation을 설계할 수 있다.
- status quo·benchmark·break-even·scenario와 가장 강한 반대논리를 만들 수 있다.
- historical mode은 공개 사후성과가 있거나 current mode은 명확한 monitoring trigger가 있다.
- outcome의 인과 한계를 설명할 수 있다.

#### Gate H — 분석 실행가능성

- 작은 source/활성화 module pilot로 grain, cut-off, 정정, terms, currency·unit과 병목을 확인했다.
- core와 optional scope를 분리할 수 있다.
- 일정은 source 처리량, 모델 의존관계와 review 필요에서 산출할 수 있다.

비활성 module은 N/A와 이유를 기록하며 gate failure가 아니다. 선택한 case에 적용되는 필수 gate 하나가 실패하면 다른 강점으로 상쇄하지 않는다. aggregate grain으로 줄이거나 더 공개적인 case·mode로 바꾼다.

## 4. Decision object·대안·version semantic

### 4.1 대안 taxonomy

대안은 후보 언어다. 모든 case에 전부 채우지 않는다.

| Option type | P3 정의 | 포함 조건 | 주요 output |
|---|---|---|---|
| HOLD_STATUS_QUO | 현재 공개된 사업·자본정책을 지속 | 비교가능한 counterfactual이 필요 | baseline cash flow·risk |
| DEFER_STAGE | 정보를 기다리거나 단계적으로 commitment | 기다림의 정보가치·기회비용이 material | option value·milestone |
| BUILD_ORGANIC | 내부역량·capex·opex로 신사업/확장 | driver·capacity·ramp를 공개근거로 모델 가능 | project NPV·cash trough |
| PARTNER_CONTRACT | 계약·유통·기술제휴 | contribution·economics·termination을 공개/시나리오로 정의 | sharing economics·dependency |
| JV | 공동지배 arrangement | 공개된 권리·의무·ownership·funding이 있음 | attributable CF·governance risk |
| MINORITY_INVEST | 비지배 지분 투자 | ownership, securities terms, exit·information rights를 정의 | investment value·dilution·exit |
| BUY_CONTROL | 사업·법인의 지배력 취득 | consideration·funding·standalone/pro forma가 모델 가능 | max price·combined value |
| DIVEST_SELL | asset·segment·subsidiary 매각 | proceeds·lost CF·stranded cost를 모델 가능 | after-tax proceeds·remaining value |
| SPIN_SEPARATE | 법적 분리·배분 | standalone·separation·capital structure 공개 가능 | SOTP·standalone liquidity |
| CLOSE_ABANDON | 운영중단·asset 회수 | exit cost·liability·salvage·lost option 정의 | abandonment value |
| RETURN_CAPITAL | dividend·buyback | residual investment opportunity와 liquidity 비교 가능 | per-share·capital structure effect |
| DELEVER | debt repayment·refinancing | maturity·rate·liquidity 공개 가능 | interest·risk·WACC effect |

### 4.2 Status quo와 defer의 분리

- status quo: 현재 운영·투자정책이 명시한 horizon 동안 계속된다는 counterfactual
- defer: 특정 milestone까지 irreversible commitment를 미루고 정보·선택권을 보존하는 적극적 대안

defer에는 기다림의 비용을 포함한다.

- 놓치는 현금흐름과 시장 선점
- 가격·금리·규제변화 노출
- option preservation과 정보개선
- 계약·license·capacity expiration

### 4.3 대안 관계

각 option pair에 다음 관계를 기록한다.

- mutually exclusive: 둘 중 하나만 선택
- compatible: 병행 가능
- sequential: 하나가 다른 대안의 전제
- contingent: event 발생 시 활성화
- reversible / partly reversible / irreversible

가중 score로 관계를 숨기지 않는다. sequential decision은 decision tree 또는 단계별 cash flow로 표현한다.

### 5.6 Cut-off와 vintage 정책

#### Ex-ante model

- information_cutoff 이전 공개자료만 input
- 같은 날 자료는 실제 공개 timestamp와 시장 접근가능성을 확인
- 정확한 공개시각이나 당시 이용가능성을 확인할 수 없으면 cutoff input에서 제외하거나, 보수적으로 다음 공개기간부터 이용 가능했던 것으로 처리하고 이유를 기록
- 이후 정정은 outcome/revision log에만 두고 원 version을 보존
- historical market price·FX·rate는 당시 관측값을 사용

#### Current model

- 동일 as-of date로 financials·market data·transaction terms를 정렬
- 최신 공시라도 대상기간·발표지연을 기록
- pending transaction의 미확정 terms는 range 또는 contingent state

#### Outcome analysis

- announcement, close와 control transfer를 구분
- pre-close public performance와 post-close consolidated result의 scope 차이를 조정
- first-reported actual과 later restatement를 분리
- acquisition/divestiture, FX, 회계정책·segment change를 organic performance와 분리

### 5.7 License·공개·재현성

- source register에 이용약관 URL, 확인일, attribution, 저장·가공·재배포 범위를 기록한다.
- 공개 repository에는 원문 재배포 권리가 없으면 locator·hash·extraction script·derived fact만 둔다.
- 상용자료가 필요한 cross-check는 공개 대체자료와 결과 차이를 설명한다.
- 원문·row·derived snapshot은 이용조건이 저장·가공·재배포를 명시적으로 허용하는 범위에서만 남긴다. 허용범위가 불명확하면 원문을 복제하지 않고 locator·hash·재현절차·합법적인 공개 대체자료를 남긴다.
- source API가 변경되거나 종료돼도 핵심 숫자를 검토할 수 있도록, 허용된 derived output 또는 공개 대체자료와 재현절차를 보존한다.
- 개인정보·비밀키·유료 원문·계약상 금지된 row를 포함하지 않는다.

### 6.2 계산 흐름

~~~text
Public facts + explicit assumptions
~~~

### 6.3 Spreadsheet·model 구조

- input·formula·output·check를 시각적·논리적으로 분리
- 한 assumption의 single source of truth
- hard-code는 source/assumption register와 연결
- formula를 row·period across에서 일관되게 유지
- 숨은 plug·unexplained residual·manual overwrite 금지
- currency·unit·sign·tax·nominal/real convention을 첫 화면에 표시
- merged cell·과도한 이름·복잡한 nesting보다 검토 가능한 단순구조 선호
- model version, change author, change reason, reviewer finding과 rollback point 보존

### 6.4 자동 checks

아래 check는 활성화한 module에만 적용하고 나머지는 N/A와 이유를 기록한다.

#### Source·version

- 중복 source_id·fact key 없음
- release timestamp가 information cutoff를 넘지 않음
- first-filed와 restated가 동일 version에 혼합되지 않음
- required access/license metadata 누락 없음

#### Accounting

- Assets = Liabilities + Equity
- beginning cash + net cash change = ending cash
- debt·share count·retained earnings roll-forward
- acquisition consideration·funding·cash paid reconciliation
- divestiture asset/liability removal과 proceeds reconciliation

#### Incremental

- option total − status quo = incremental bridge
- incremental components + residual = total difference
- sunk cost 제외, opportunity cost·cannibalization review 완료
- capex·depreciation·tax·working capital sign·timing 일치
- project와 financing cash flow double count 없음

#### Transaction·pro forma

- historical + Transaction Accounting Adjustments + 해당 시 Autonomous Entity Adjustments = filed Article 11 pro forma
- 선택적인 Management’s Adjustments는 설명주석의 reconciliation으로 확인하며 filed pro forma total에 합산하지 않음
- ownership·exchange ratio·new shares·EPS denominator reconcile
- consideration transferred, transaction EV, equity purchase price, closing cash paid와 cash Sources/Uses가 각각 정의되고 상호 reconcile
- synergy·integration·PPA adjustment 중복 없음
- forward-looking analyst case가 factual pro forma 열에 섞이지 않음

#### Valuation

- cash-flow definition과 discount rate의 capital-provider·tax·currency basis 일치
- terminal value 기준과 explicit period 연결
- IRR multiple root·non-conventional cash flow warning
- max-price solver가 목표 NPV 또는 constraint와 역산 일치

#### Decision

- memo·dashboard·snapshot의 key output이 model과 일치
- 모든 [R]에 decision condition·no-go·monitoring trigger가 있음
- material limitation과 strongest counterargument 누락 없음

### 6.5 단위·통화·세금·물가 convention

모든 option에 동일 convention을 강제하기보다 비교 가능한 basis를 강제한다.

- nominal cash flow ↔ nominal discount rate
- real cash flow ↔ real discount rate
- local currency ↔ 해당 통화의 discount rate; 환산 시 FX path와 date 명시
- pre-tax ↔ pre-tax rate, after-tax ↔ after-tax rate를 임의 혼합하지 않음
- tax는 statutory rate만 기계적으로 쓰지 않고 공개된 loss carryforward·jurisdiction·deductibility 한계를 [A]로 분리
- accounting depreciation과 tax depreciation을 구분할 자료가 없으면 단순화와 영향을 공개

## 7. 의사결정 범위와 standalone baseline

### 7.1 Decision unit

decision unit은 현금흐름을 독립적으로 식별할 수 있는 공개 grain으로 정한다.

- 공개 segment가 없다면 가상의 product P&L을 actual로 만들지 않는다.
- segment 정보가 바뀌면 comparable period를 재작성하거나 limitation 표시
- shared cost 배분을 공개할 수 없으면 avoidable·unavoidable range로 시나리오화
- 금융회사는 regulatory entity와 consolidated group의 자본·유동성을 혼합하지 않는다.

### 7.2 Status-quo baseline

status quo는 단순히 최근 실적을 평행이동한 값이 아니다.

- 현재 공개된 capacity·pricing·contract·regulation·capital policy
- maintenance capex와 working capital
- 경쟁·잠식·제품수명·funding cost
- 이미 committed된 공개 투자와 확정 restructuring
- 공개된 guidance는 management view로 별도 보존

Analyst baseline은 공개근거와 [A]로 독립 작성한다. management guidance를 복사한 경우 이유와 차이를 설명한다.

### 7.3 Standalone normalization

case에 필요한 경우 다음을 분리한다.

- continuing vs discontinued operation
- organic vs acquired/divested scope
- recurring vs transaction·restructuring item
- reported vs adjusted metric
- lease·stock compensation·capitalized development 등 평가 관련 항목
- consolidated vs equity-method/JV contribution
- gross debt, cash, restricted cash와 net debt convention

조정은 경제적 질문과 연결될 때만 한다. non-GAAP 조정을 자동으로 더 정확한 경제값이라 보지 않는다.

### 7.4 Standalone model

~~~text
Operating drivers
→ Revenue
→ Variable/fixed/step costs
→ EBITDA/operating profit
→ Taxes
→ Maintenance/growth capex
→ Depreciation/amortization
→ Working capital
→ Operating cash flow / FCFF
→ Debt, cash, interest where needed
→ Equity value or capital capacity
~~~

P1 model을 재사용하면 source vintage, scope와 assumption version을 P3 case에 맞게 freeze한다. P3용 숫자를 P1 historical에 역으로 덮어쓰지 않는다.

### 7.5 Counterfactual 한계

status quo는 관측되지 않은 세계다. 특히 historical outcome study에서는 다음을 명시한다.

- 거래가 없었어도 산업·금리·FX·경쟁이 변했을 가능성
- 다른 투자·매각·자금조달이 동시에 일어났을 가능성
- public peer가 완전한 counterfactual이 아님
- post-event management가 바뀌고 reporting scope가 달라질 가능성

따라서 outcome은 model calibration과 판단 검토에 사용하되 causal proof로 표현하지 않는다.

## 8. Incremental after-tax cash flow

### 8.1 핵심 identity

[CALC] 각 option의 경제적 현금흐름은 동일 as-of status quo와의 차이로 정의한다.

~~~text
Incremental CF_t(option)
= CF_t(option world)
− CF_t(status-quo world)
~~~

project/enterprise basis 예시:

~~~text
Incremental FCFF_t
= Incremental EBIT_t before separately scheduled implementation/integration/separation items
+ Incremental non-cash charges_t
− Incremental cash taxes_t on EBIT and all separately scheduled items
− Incremental capex_t
− Δ Incremental net working capital_t
− Incremental implementation/integration/separation cash cost_t not already included in EBIT, before related cash-tax effects
+ Incremental disposal/salvage cash proceeds_t net of selling costs, before related cash-tax effects
± Other directly caused enterprise cash effects_t before tax unless explicitly flagged after-tax

Δ Incremental NWC_t
= [NWC_option,t − NWC_option,t−1]
− [NWC_status-quo,t − NWC_status-quo,t−1]
~~~

이는 구현 template이며 공개자료와 case 특성에 맞게 line을 수정한다. cash-tax schedule은 위 개별항목의 공제·양도세·거래세를 모두 한 번만 반영한다. 공개 source가 개별항목을 net-of-tax로만 제시해 그 값을 사용하면 해당 세금효과를 cash-tax line에서 제외하고 tax_basis flag와 reconciliation을 남긴다. cash tax를 합리적으로 근사할 수 있는 경우에만 Incremental EBIT × (1 − tax rate)를 shortcut으로 쓰고, loss carryforward·jurisdiction·deductibility·transaction tax가 중요한 경우 실제 cash-tax schedule을 우선한다. 종료 시 NWC 회수도 별도 cash flow로 반영한다. initial project/transaction outlay는 Incremental CF_0 또는 별도 acquisition-NPV bridge 중 한 곳에서만 반영한다.

### 8.2 포함 원칙

- 대안을 선택했기 때문에 달라지는 현금만 포함
- 세후 basis와 실제 지급 timing 반영
- 기존 사업의 positive spillover와 negative cannibalization 포함
- shared capacity·management attention·regulatory capital의 opportunity cost 검토
- maintenance와 growth investment 구분
- 직접적인 implementation·integration·separation·exit cash cost 포함
- contract·license·decommission·environmental·customer remediation 등 공개된 liability 검토
- terminal/exit cash flow와 잔존 working capital 회수 검토

### 8.3 매몰비용

이미 지출되어 현재 대안으로 바뀌지 않는 비용은 의사결정 cash flow에서 제외한다.

- 과거 R&D·consulting·failed pilot
- 이미 발생한 공시·advisory cost
- 회수 불가능한 과거 capex

단, 매몰비용은 governance·forecast bias·향후 commitment의 학습 증거가 될 수 있다. 경제성 계산에서 제외하되 decision narrative에서 무시하지 않는다.

### 8.4 기회비용

보유 asset·cash·capacity를 사용하면 장부상 지출이 없어도 최선의 실행 가능한 대안에서 얻을 수 있었던 현금을 반영한다.

- idle-looking property의 매각·임대가치
- cash 사용으로 포기한 interest/debt reduction
- scarce regulatory capital·engineering capacity
- channel·customer attention의 대체 사용

기회비용의 대안이 실제로 가능하고 공개근거가 있을 때만 포함한다.

cash 보유·debt paydown의 기회비용은 서로 배타적인 자본배분 대안의 incremental NPV로 비교하거나 APV/FCFE 등 선택한 자금조달 접근에서 일관되게 처리한다. FCFF/WACC 접근에서는 포기한 이자수익이나 debt reduction 편익을 operating cash flow에 넣고 다시 할인율·net debt·financing schedule에 반영하는 이중계상을 금지한다.

근거: [CFA Capital Investments and Capital Allocation](https://www.cfainstitute.org/insights/professional-learning/refresher-readings/2026/capital-investments-and-capital-allocation), [HM Treasury Green Book 2026](https://www.gov.uk/government/publications/the-green-book-appraisal-and-evaluation-in-central-government/the-green-book-2026). Green Book은 기업가치평가 기준이 아니라 option·opportunity cost·switching-value 사고의 유사 근거로만 사용한다.

### 8.5 Cannibalization·synergy·dis-synergy

기존 제품·segment 매출 감소는 대안의 손실로, 교차판매·shared infrastructure 절감은 이익으로 포함한다.

- gross headline synergy가 아니라 incremental after-tax cash로 변환
- synergy와 standalone improvement를 분리
- revenue synergy에는 volume, price, churn, margin, ramp와 capacity 필요
- cost synergy에는 비용 base, avoidability, timing, severance·closure cost 필요
- integration distraction, customer loss, system duplication, compliance cost도 dis-synergy 후보
- 동일 효과가 standalone forecast·purchase price·synergy에 중복되지 않는지 check

### 8.6 Working capital·capex·tax

- 매출성장만 모델링하고 receivable·inventory·settlement·collateral·regulatory reserve를 누락하지 않는다.
- capex는 initial, maintenance, expansion, replacement와 decommission을 구분한다.
- tax loss·interest deductibility·transaction tax·capital-gain tax·jurisdiction은 공개자료 범위에서 반영한다.
- 정확한 세무처리를 검증할 자료가 없으면 statutory/simple cash-tax scenario와 limitation을 제시한다.

### 8.7 Project cash flow와 financing cash flow

두 접근 중 하나를 일관되게 선택한다.

#### Enterprise/project approach

- financing 전 FCFF 또는 project cash flow
- risk-matched WACC/project discount rate
- debt·equity funding은 별도 liquidity/capital structure 분석

#### Equity approach

- FCFE = net income + non-cash charges − fixed-capital investment − working-capital investment + net borrowing
- interest는 net income·cash tax에, debt principal은 net borrowing에 반영
- common-equity issuance, buyback과 dividend는 FCFE에 넣지 않고 ownership·share-count·distribution schedule에서 별도 반영
- FCFE는 cost of equity로 할인
- 특정 투자자의 initial equity contribution과 회수액을 모델링하면 FCFE가 아니라 cash flow to equity investors로 명명해 equity NPV/IRR 계산

[JUDG] 금융회사 분석 convention: 규제 금융회사는 deposits·borrowings·insurance liabilities·interest·regulatory capital이 operating item인지 먼저 판정한다. 해당하면 비금융 FCFF/WACC·net-debt EV·NWC convention을 자동 적용하지 않고 FCFE·dividend·residual-income 또는 distributable-capital framework를 사용하며 transaction price·cash flow·discount rate의 equity basis를 맞춘다. 실제 case의 CET1/RWA·solvency·배당가능성 등 규제자본 제약은 해당 감독기관의 공식 규정과 회사 regulatory filing에 연결한다.

FCFF에 interest를 차감하고 WACC로 할인하거나, acquisition price에 debt를 포함한 뒤 enterprise value에서 다시 차감하는 double count를 금지한다.

근거: [CFA Capital Investments and Capital Allocation](https://www.cfainstitute.org/insights/professional-learning/refresher-readings/2026/capital-investments-and-capital-allocation), [CFA Free Cash Flow Valuation](https://www.cfainstitute.org/insights/professional-learning/refresher-readings/2026/free-cash-flow-valuation), [IAS 7 Statement of Cash Flows](https://www.ifrs.org/issued-standards/list-of-standards/ias-7-statement-of-cash-flows/)

## 9. 가치평가·자본효율 지표

### 9.1 NPV

[STD] NPV는 project의 현금흐름이 기업가치에 더하는 현재가치를 추정하는 지표다. [JUDG] P3는 대안별 incremental cash flow와 위험조정 할인요소를 신뢰성 있게 모델링할 수 있을 때 NPV를 우선한다. 공개자료가 그 현금흐름을 지지하지 못하면 정밀한 NPV를 강제로 만들지 않고 break-even·range·다른 적합 지표와 미산출 이유를 제시한다.

~~~text
NPV = Σ Incremental CF_t × DF_t

DF_0 = 1

기간별 one-period rate r_k를 적용할 때:
DF_t = 1 / ∏(k=1…t)(1 + r_k)
~~~

t년 spot rate s_t이면 DF_t = 1/(1+s_t)^t, 모든 기간에 같은 r을 쓰면 DF_t = 1/(1+r)^t다. 각 cash-flow maturity에 맞는 discount factor를 사용하고 one-period rate를 단일 spot rate처럼 거듭제곱하지 않는다.

사용조건:

- incremental cash flow와 timing이 합리적으로 정의됨
- discount rate의 통화·세금·risk basis가 일치
- 대안 간 scale·timing 차이를 포함
- terminal·exit가 근거와 sensitivity를 가짐

NPV가 양수여도 liquidity, covenant, 규제, 실행역량 또는 전략적 no-go를 위반하면 자동 승인하지 않는다.

### 9.2 IRR

IRR은 rate-of-return communication에 유용하지만 다음을 확인한다.

- non-conventional cash flow의 multiple/no IRR
- 규모가 다른 대안에서 NPV 순위와 충돌
- 재투자 가정과 horizon 차이
- short-lived high IRR 대안이 더 큰 가치기회를 밀어내는 문제

IRR은 단독 decision rule이 아니다.

### 9.3 ROIC

ROIC는 투자 후 운영성과와 자본효율 monitoring에 유용하다.

- project/segment/issuer ROIC의 분자·분모를 구분
- accounting allocation과 acquisition goodwill 처리 명시
- ramp 기간의 일시적 저수익과 정상상태 구분
- WACC와 비교할 때 동일 scope·시점·basis인지 확인

공개자료로 project invested capital을 식별할 수 없으면 company-level ROIC를 project ROIC처럼 표현하지 않는다.

### 9.4 Payback

payback은 liquidity·irreversibility·execution risk를 빠르게 볼 수 있지만 payback 이후 현금흐름과 자본비용을 무시할 수 있다. cash constraint가 material할 때 보조지표로 사용한다.

### 9.5 Discount rate·hurdle

고정 hurdle을 두지 않는다.

- public market capital structure, risk-free rate, credit spread, beta/peer, country·currency risk 후보
- 사업위험이 회사 평균과 다른지
- 대안별 leverage·guarantee·optionality 차이
- cash flow에 이미 확률가중·haircut된 위험과 discount rate risk premium의 중복

estimate가 불안정하면 단일 rate 대신 break-even discount rate와 범위를 보여준다.

### 9.6 Terminal value·exit

- explicit period 종료 시 사업이 정상상태인지
- 성장률이 재투자와 ROIC에 의해 뒷받침되는지
- exit multiple의 numerator/denominator와 peer basis가 일치하는지
- finite contract·license·product life이면 perpetuity가 적합한지
- divest/abandon option과 terminal을 중복하지 않는지

terminal value 비중이 결론을 지배하면 horizon 확대를 자동 답으로 쓰지 않는다. 핵심 driver·normalization·exit uncertainty를 드러내고 reverse valuation을 제공한다.

### 9.7 EPS accretion ≠ value creation

EPS는 financing mix, share issuance, interest rate, accounting amortization과 buyback으로 달라질 수 있다.

- accretive 거래도 과도한 대가·risk·현금사용으로 NPV가 음수일 수 있다.
- dilutive 거래도 장기 incremental value가 양수일 수 있다.
- pro forma EPS는 communication metric이며 현금흐름 가치판단의 대체재가 아니다.

근거: [CFA Capital Investments and Capital Allocation](https://www.cfainstitute.org/insights/professional-learning/refresher-readings/2026/capital-investments-and-capital-allocation), [CFA Corporate Restructuring](https://www.cfainstitute.org/insights/professional-learning/refresher-readings/2026/corporate-restructuring), [CFA Free Cash Flow Valuation](https://www.cfainstitute.org/insights/professional-learning/refresher-readings/2026/free-cash-flow-valuation)

## 10. Build·유기적 투자·신사업 module

### 10.1 적용 질문

- 기존 사업을 확장하는가, 새로운 product·channel·region을 구축하는가?
- full-scale commitment와 staged pilot 중 무엇이 적합한가?
- build가 buy·partner·defer보다 현금·시간·역량 측면에서 나은 조건은 무엇인가?
- 실패 시 중단·축소·asset 재사용이 가능한가?

### 10.2 공개정보 input

- 회사의 공개 사업·기술·distribution·capacity·capex·인력 방향
- 시장규모가 아니라 공개된 demand driver, 가격, adoption, regulation
- 회사·peer의 공개 margin, working-capital, capex intensity와 ramp 사례
- 공공조달·license·patent·규제승인·가격표·공개 customer case
- macro·industry official statistics

TAM을 매출로 바로 변환하지 않는다. 공개 근거가 없는 share·conversion·retention은 [A]이며, range와 break-even을 사용한다.

### 10.3 Operating schedule

~~~text
Reachable demand
× adoption/conversion
× price/take rate
= gross revenue
− variable/processing/risk/service cost
− incremental fixed/step cost
− net cannibalization/displacement operating effect, including avoided variable cost
= incremental EBIT before separately scheduled launch items
+ incremental non-cash charges
− incremental cash taxes on EBIT and all separately scheduled items
− Δ incremental operating net working capital
− incremental capex
− incremental implementation/launch cash cost not already included in EBIT, before related cash-tax effects
= incremental after-tax cash flow
~~~

cash-tax schedule과 net-of-tax 예외는 8.1의 단일계상 convention을 그대로 따른다. cannibalization은 lost gross revenue가 아니라 회피되는 variable cost 등 반대효과까지 포함한 증분 operating effect로 측정한다.

사업유형에 따라 customer 수, transaction volume, AUM, balance, capacity, utilization, claims 또는 subscription unit으로 바꾼다. 공개되지 않은 grain은 aggregate model로 줄인다.

### 10.4 Ramp와 capacity

- demand ramp와 delivery capacity ramp를 분리
- hiring·technology·license·distribution의 공개 제약 연결
- step cost와 idle capacity 구분
- initial loss·learning curve·service quality·compliance cost 반영
- capacity가 제한되면 단순 매출성장률 대신 constraint-aware path 사용

### 10.5 Staged investment와 real option

단계별 investment는 다음을 기록한다.

| Stage | Commitment | 공개 milestone | 다음 선택 | 추가 cash | 중단 시 회수/비용 | 정보가치 |
|---|---:|---|---|---:|---:|---|
| Pilot |  |  | expand/defer/stop |  |  |  |
| Scale |  |  | expand/partner/stop |  |  |  |
| Mature |  |  | maintain/divest |  |  |  |

위 행은 설명용 예시다. 실제 stage의 수·명칭·milestone은 공개된 기술·계약·규제·capacity 경로에서 정한다.

단계를 나누는 것 자체를 가치로 더하지 않는다. flexibility의 가치와 대기·실행 비용을 함께 본다.

### 10.6 Build no-go·monitoring

아래 상태는 P3가 공개자료 범위에서 build를 추천·release하지 않는 조건이지, 실제 회사가 투자해서는 안 된다는 사실판정이 아니다. 핵심 input을 공개자료로 확인할 수 없어 결론이 달라질 수 있으면 NO_GO 대신 INSUFFICIENT_PUBLIC_EVIDENCE로 두고 실제 내부 검토에서 요청할 자료를 적는다.

- 공개근거가 뒷받침하지 못하는 최소 adoption·margin이 NPV=0 조건보다 높음
- funding·liquidity·capital 제약 위반
- 공개된 license·regulatory approval·critical capability 경로가 실행불가능함. 단, 비공개 확인이 필요한 경우 INSUFFICIENT_PUBLIC_EVIDENCE
- cash trough가 공개된 가용자원 범위를 넘음
- pilot milestone이 다음 commitment 전에 측정 불가

수치는 case의 공개 제약과 break-even에서 도출한다.

## 11. Buy·M&A module

### 11.1 관점 고정

같은 거래도 관점이 다르다.

- acquirer shareholder: 지급대가 이후 incremental value
- target shareholder: offer value·form·certainty·alternative
- combined entity: operating·financing·accounting effect
- creditor: leverage·coverage·liquidity·structural subordination

P3 core는 한 관점을 명시하고 다른 관점은 필요할 때 별도 memo로 확장한다.

### 11.2 공개정보 기반 screening

screening 기준은 거래후보 수를 줄이기 위한 점수가 아니라 경제적 fit을 확인하는 질문이다.

- strategic problem과 target capability가 직접 연결되는가?
- build·partner·status quo가 더 낮은 비용·위험으로 같은 목적을 달성할 수 있는가?
- standalone business와 공개 재무가 이해 가능한가?
- ownership·control·regulatory path가 실행 가능한가?
- valuation·funding·integration downside를 공개자료로 모델링할 수 있는가?
- seller/target의 공개 동기와 closing condition을 설명할 수 있는가?

공개되지 않은 acquisition pipeline을 발굴했다고 표현하지 않는다.

### 11.3 Public-source desktop diligence

| Workstream | 공개자료로 확인 가능한 후보 | 공개자료만으로 남는 gap |
|---|---|---|
| Financial | audited filings, segment, cash flow, debt, related party, auditor note | quality of earnings 상세, monthly trial balance, customer profitability |
| Commercial | market statistics, pricing, public customers, contracts disclosed, competitors | pipeline, churn cohort, win/loss, confidential contract economics |
| Operational | capacity, facilities, headcount aggregate, product/SLA 공개자료 | process data, code/IP verification, cyber evidence, retention plan |
| Legal/regulatory | filings, litigation/regulatory actions, license registers, statutes | full contract, privileged advice, undisclosed contingency |
| Tax | public tax note, jurisdiction, loss carryforward disclosures | tax return, basis, audit exposure, structure-specific ruling |
| ESG/other | official permits, sanctions, public incident, disclosed liability | site-level/environmental diligence, non-public remediation |

결과는 red flag·evidence gap·decision impact·필요한 실제 diligence request를 제시한다. full diligence 완료라고 하지 않는다.

### 11.4 Target standalone value

- target historical normalization과 independent forecast
- management projection은 실제 공개된 경우에만 PUBLIC_MANAGEMENT_VIEW
- DCF·trading comps·precedent·premium-paid 중 적합한 방법 선택
- private/non-listed target은 법정공시가 충분할 때만 제한 분석
- control·marketability adjustment는 case-specific evidence 없이 고정 적용 금지

target standalone value와 buyer-specific synergy value를 섞지 않는다.

### 11.5 Consideration bridge·closing cash sources and uses

거래대가, transaction EV와 종결일 현금조달표를 하나의 총계에 섞지 않는다.

~~~text
Consideration transferred — IFRS 3 illustrative
= acquisition-date fair value of non-contingent assets transferred by the acquirer
+ acquisition-date fair value of non-contingent liabilities incurred to former owners
+ acquisition-date fair value of non-contingent equity interests issued to former owners
+ acquisition-date fair value of contingent consideration, whether liability- or equity-classified
± other consideration transferred to former owners not already included

Transaction EV bridge
= equity purchase price
+ debt and debt-like items assumed
− cash and cash-like items acquired
± other explicitly supported EV adjustments

Closing cash Uses
= cash paid to sellers at close
+ target debt actually repaid or refinanced at close
+ transaction and financing fees paid at close
+ other closing cash uses

Closing cash Sources
= acquirer cash used
+ new debt cash proceeds
+ separate cash-equity proceeds
+ asset-sale and other financing cash proceeds
~~~

[CALC] Closing cash Sources = Closing cash Uses를 check한다.

seller에게 직접 교부한 주식, 아직 현금 지급되지 않은 contingent consideration, cash가 실제 유입되지 않는 seller note와 승계하되 closing에서 상환하지 않는 target debt는 cash Sources/Uses에 넣지 않는다. 비현금 항목까지 포함한 별도 total Sources/Uses를 제시하려면 현금·비현금 열을 나누고 양쪽에 대칭 표시한다. assumed debt는 transaction EV↔equity bridge와 post-close debt에서 추적하되 같은 경제적 부담을 다시 consideration·cash use로 더하지 않는다. refinancing fee·premium은 실제 현금 use로 분리한다.

주식대가는 무료가 아니다.

- exchange ratio와 발행주식 수
- announcement·measurement·close date의 가격 차이
- ownership transfer와 dilution
- collar·minimum/maximum·contingent term

를 분리한다. IFRS 3의 회계상 consideration transferred와 IAS 7의 현금흐름 표시를 거래 경제성 산식과 혼동하지 않는다.

근거: [IFRS 3 Business Combinations](https://www.ifrs.org/issued-standards/list-of-standards/ifrs-3-business-combinations/), [IAS 7 Statement of Cash Flows](https://www.ifrs.org/issued-standards/list-of-standards/ias-7-statement-of-cash-flows/)

### 11.6 EV↔equity bridge

~~~text
Enterprise value
− debt and debt-like items
+ cash and eligible non-operating assets
± other explicitly supported adjustments
= equity value
~~~

debt-like·cash-like 항목은 정의와 공개근거가 있을 때만 조정한다. pension, lease, factoring, restricted cash, minority interest와 associates는 거래·valuation basis에 맞게 일관되게 처리한다.

[JUDG] 규제 금융회사처럼 debt·cash가 영업자산·영업부채 성격을 갖는 경우 이 비금융 EV bridge를 자동 적용하지 않는다. equity purchase price와 equity-basis valuation, 해당 감독기관 규정과 회사 공시에 따른 규제자본·분배가능자본을 직접 연결한다.

### 11.7 IFRS 3 illustrative accounting overlay

먼저 acquired set가 ‘business’이고 거래가 IFRS 3 적용범위인지 확인한다. asset acquisition이나 common-control combination에는 acquisition-method goodwill bridge를 적용하지 않는다. 공개정보로 scope를 판단할 수 없으면 SCOPE_NOT_OBSERVABLE로 두고 회계결론을 내리지 않는다. IFRS 3 적용대상이고 취득일 공정가치 정보가 공개되었거나 각 fair-value adjustment를 명시적 analyst assumption으로 분리할 수 있을 때만 다음 bridge를 활성화한다.

~~~text
Fair value of consideration transferred
+ amount of any non-controlling interest in the acquiree
+ fair value of previously held interest
− acquisition-date fair value of identifiable net assets acquired
= reported or explicitly illustrative goodwill / pre-reassessment bargain-purchase indication
~~~

공개자료의 깊이에 따라 output label을 다르게 쓴다.

- 공개 consideration과 book net assets만 있으면 consideration less reported book net assets 또는 unallocated purchase-price gap으로 표시한다. 이를 goodwill로 부르지 않는다.
- 회사의 provisional/final PPA가 공개되면 identifiable assets·liabilities, NCI, tax와 goodwill을 원 공시에 reconcile한다.
- analyst가 fair-value adjustment·tax·useful life를 가정하면 illustrative PPA sensitivity로 명시하고 range를 붙인다. 이는 IFRS 측정이나 회계결론이 아니다.
- public provisional PPA와 후속 확정 사이의 변경을 별도 vintage로 보존한다.

다음은 확정하지 않는다.

- 최종 intangible fair value·useful life
- unrecorded liability·tax basis·deferred tax
- CGU allocation·final goodwill
- management valuation specialist conclusion

Goodwill은 가치창출 증거가 아니다. 취득대가, 해당 NCI·기존보유지분과 취득일 공정가치 기준 식별가능 순자산 사이의 회계상 잔여다. 음의 잔여는 즉시 확정 bargain-purchase gain으로 부르지 않고 IFRS 3이 요구하는 재검토 전 indication으로 표시한다.

근거: [IFRS 3 Business Combinations](https://www.ifrs.org/issued-standards/list-of-standards/ifrs-3-business-combinations/)

### 11.9 Integration·restructuring cash cost

- system migration·duplicate platform
- severance·retention·facility closure
- TSA·standalone transition
- customer/vendor remediation
- compliance·license·data migration
- duplicated capex·working-capital disruption
- management distraction·customer loss

공시되지 않은 정확한 비용은 점추정치로 발명하지 않는다. 공개 peer·company guidance가 있으면 range, 없으면 break-even capacity 또는 ‘not observable’로 둔다.

비용 성격별 schedule을 분리한다.

- advisor·legal 등 acquisition-related transaction cost: buyer-side transaction-cost schedule에 두고 consideration·goodwill·integration cost와 분리한다. IFRS 3에서는 원칙적으로 발생시 비용이며, debt/equity issue cost는 별도 기준으로 처리한다.
- debt·equity issuance cost: funding schedule에 두고 [IFRS 9](https://www.ifrs.org/issued-standards/list-of-standards/ifrs-9-financial-instruments/)·[IAS 32](https://www.ifrs.org/issued-standards/list-of-standards/ias-32-financial-instruments-presentation/) 등 적용 회계기준과 현금 timing을 확인하며 operating FCFF에 넣지 않는다.
- integration·restructuring cost: 실제 통합으로 생기는 incremental after-tax operating cash flow로 모델링하되 standalone·synergy·P&L에 이미 들어간 금액은 제외한다.

각 cash item은 하나의 source_id와 schedule에 연결하고 경제성 계산에는 한 번만 반영한다.

### 11.10 Pro forma와 forecast의 분리

현행 SEC amended Article 11은 Transaction Accounting Adjustments, 해당되는 경우 Autonomous Entity Adjustments, 선택적인 Management’s Adjustments를 구분한다. P3는 SEC filing compliance를 주장하지 않지만 그 의미구분을 참고한다.

Article 11의 face statements는 condensed balance sheet와 statement(s) of comprehensive income 및 notes이고 cash-flow statement를 필수 pro forma face로 간주하지 않는다. P3의 integrated combined cash-flow schedule은 analyst model이며 filed Article 11 pro forma가 아니다.

| 층 | 목적 | 포함 | 금지 |
|---|---|---|---|
| Historical standalone | 거래 전 실제상태 | acquirer·target historical | 미래 시너지 |
| Transaction-accounting adjustment | 거래 회계효과 | required accounting에 해당하는 purchase/funding/accounting adjustment | analyst ramp·미검증 synergy |
| Autonomous Entity Adjustments | registrant가 이전에 다른 entity의 일부였던 경우 독립 entity로서 필요한 operations·financial position 표시 — 해당 시 | 규정상 필요하고 공개근거가 있는 adjustment | 단순히 target 사업이 carve-out이라는 이유만으로 적용하거나 공개되지 않은 corporate-cost allocation 발명 |
| Management’s Adjustments | 실제 SEC 공시에 선택적으로 제시된 synergy·dis-synergy — 있을 때만 | explanatory note에서 filed pro forma net income과 EPS를 조정한 reconciliation·근거·scope | filed pro forma total에 합산하거나 realized fact·analyst base로 자동 전환 |
| Forward-looking analyst combined case | 향후 경제전망 | explicit standalone forecast, analyst synergy/dis-synergy, integration | audited/official pro forma라고 표현 |

historical, Transaction Accounting Adjustments, 해당 시 Autonomous Entity Adjustments, filed pro forma, 선택적 Management’s Adjustments reconciliation과 analyst forecast를 분리하고 모든 adjustment를 footnote/source에 연결한다. 실제 SEC Management’s Adjustments를 인용하면 reasonable basis, 관련 dis-synergy의 동시 표시, 역사적 비용을 넘는 cost reduction 금지, basis·material limitation·assumption·uncertainty·계산·timing 공시를 원문에서 확인한다. P3의 표는 분석 통제 convention이며 SEC 제출양식 자체가 아니다.

근거: [17 CFR § 210.11-02](https://www.ecfr.gov/current/title-17/chapter-II/part-210/article-11/section-210.11-02), [SEC — Financial Disclosures about Acquired and Disposed Businesses](https://www.sec.gov/resources-small-businesses/small-business-compliance-guides/financial-disclosures-about-acquired-disposed-businesses), [SEC — Final Rule 33-10786](https://www.sec.gov/files/rules/final/2020/33-10786.pdf), [SEC Financial Reporting Manual](https://www.sec.gov/files/cf-frm.pdf) — staff guidance, non-authoritative

### 11.11 Combined model

~~~text
Combined operating FCFF_t
= Acquirer standalone FCFF_t
+ Target standalone FCFF_t
+ Gross after-tax operational synergy_t
− After-tax dis-synergy_t
− After-tax integration/restructuring cash cost_t not included elsewhere

Combined operating enterprise value
= PV(Combined operating FCFF)

Combined equity value
= Combined operating enterprise value
− debt and debt-like items
+ cash and supported non-operating assets
± other supported EV-to-equity adjustments
~~~

transaction-accounting·PPA·amortization은 reported P&L/BS pro forma layer에, financing·interest·debt·shares는 liquidity·FCFE·EPS layer에 둔다. 실제 cash-tax 효과는 선택한 cash-flow layer에 한 번만 넣는다. operating value와 financing/accounting communication을 한 표 안에서 보여도 계산 layer는 분리한다.

### 11.12 Maximum price

[CALC][JUDG] acquirer 관점에서 NPV=0이 되는 가격을 역산한다. 아래 bridge는 공식기관이 의무화한 단일식이 아니라, target standalone value와 buyer-specific incremental cash flow를 동일 as-of·currency·ownership·tax·discount·EV/equity basis로 맞춘 경우의 P3 계산 convention이다.

개념적으로:

~~~text
Maximum acquisition EV at NPV = 0
= Target standalone EV
+ PV(gross after-tax operating synergy)
− PV(after-tax dis-synergy)
− PV(after-tax integration, transaction and other buyer cash costs not included elsewhere)
− PV(opportunity and cannibalization cash costs)
± PV(other supported enterprise cash effects)

Maximum equity purchase price
= Maximum acquisition EV
− debt and debt-like items assumed
+ cash and cash-like items acquired
± other explicitly supported EV-to-equity adjustments
~~~

assumed debt는 acquisition EV에 한 번만 포함하고 equity price로 bridge할 때 차감한다. 이미 EV에 포함된 debt를 cash use나 total economic outlay에 다시 더하지 않으며, 실제 상환·refinancing은 closing liquidity와 fee·timing schedule에서 추적한다. 규제 금융회사는 이 EV 공식을 자동 적용하지 않고 동일한 equity basis에서 maximum equity purchase price를 직접 역산한다.

- risk cushion을 별도로 뺀다면 공식 표준이 아니라 [JUDG] policy이며 근거·변경조건 표시
- headline offer와 total economic outlay 비교
- contingent consideration·fees·refinancing 누락 금지
- price per share, exchange ratio와 total consideration reconciliation

### 11.13 Reverse-implied synergy

offer가 공개됐다면 acquisition EV를 정당화하는 gross operating synergy를 역산한다.

~~~text
Required gross operating synergy PV
= Acquisition EV actually paid
− Target standalone EV
+ PV(after-tax cash effects of dis-synergy, integration, transaction, opportunity and cannibalization)
− PV(other supported buyer-specific enterprise value)
~~~

회사가 발표한 synergy와 required synergy의 as-of·currency·ownership·scope·세금·timing·discount basis를 맞춘 뒤 비교한다. 차이를 바로 ‘overpayment’으로 단정하지 않고 공개되지 않은 옵션·strategic value와 정보 gap을 limitation으로 둔다.

근거: [CFA Capital Investments and Capital Allocation](https://www.cfainstitute.org/insights/professional-learning/refresher-readings/2026/capital-investments-and-capital-allocation), [CFA Corporate Restructuring](https://www.cfainstitute.org/insights/professional-learning/refresher-readings/2026/corporate-restructuring)

### 11.14 M&A no-go

아래 상태는 P3가 공개자료 범위에서 buy를 추천·release하지 않는 조건이지 실제 거래의 당위성을 확정하는 것이 아니다. 공개정보 부족만으로 부정판정을 만들지 않고, 결론을 좌우하는 미확인 항목은 INSUFFICIENT_PUBLIC_EVIDENCE와 실제 diligence request로 전환한다.

- maximum price보다 total economic outlay가 높고 공개근거로 설명되지 않음
- 공개자료로 확인된 liquidity·capital·covenant·approval 제약 위반
- base NPV가 단일 미검증 revenue synergy에 의존
- 중대한 public-source red flag가 미해소이면 P3 recommendation을 보류하고 실제 diligence를 요청. 공개정보만으로 해소 여부를 판단할 수 없으면 INSUFFICIENT_PUBLIC_EVIDENCE
- integration cost·customer loss·working-capital shock의 break-even 여유가 없음
- pro forma가 transaction fact와 analyst forecast를 혼합

## 13. Divest·spin-off·closure module

### 13.1 Divestiture cash flow

[CALC] 최상위 identity는 다른 대안과 같다.

~~~text
Incremental divestiture CF_t
= CF_t(divest world) − CF_t(status-quo world)

Detailed bridge
Incremental divestiture CF_t
= Cash proceeds_t net of selling costs, before related cash-tax effects
− Lost standalone cash operating contribution_t before cash taxes and before the separately listed items below
− Separation/TSA/restructuring cash cost_t before related cash-tax effects
− Stranded-cost and dis-synergy cash outflow_t before related cash-tax effects
− Expected retained-liability cash outflow_t before related cash-tax effects
± Operating working-capital release/investment_t
+ Incremental cash distributable or redeployable from regulatory-capital release_t — regulated entity only
+ Avoided future capex and other investment cash outflow_t
− Incremental cash taxes_t on all operating, disposal, separation and retained-liability items versus status quo

Incremental divestiture NPV
= Σ Incremental divestiture CF_t × DF_t
~~~

bridge의 각 항목은 net proceeds, lost contribution 또는 다른 schedule에 아직 포함되지 않은 금액만 기록한다. cash-tax schedule은 모든 세금효과를 한 번만 반영하고, 공개 source의 after-tax item을 그대로 쓰면 대응 세금을 tax line에서 제외해 flag·reconcile한다. 일시점 proceeds와 여러 기간의 lost·avoided cash flow를 명목금액으로 바로 더하지 않는다. 모두 동일 as-of·currency·tax·discount basis로 변환한다. abstract risk를 별도 현금차감으로 더하지 않고 기대현금흐름·scenario·discount rate 중 선택한 위치에 한 번만 반영한다. debt repayment·capital return처럼 매각대금의 financing use는 operating divestiture value와 분리한 뒤 통합한다.

### 13.2 Proceeds

- headline price와 cash received 분리
- debt transfer·assumption
- transaction tax·fee·closing adjustment
- earn-out·seller financing·escrow
- retained stake·contingent liability
- proceeds 사용: debt paydown·reinvestment·capital return

buyer가 assumed/transferred debt는 headline EV↔equity price↔cash proceeds bridge에서 한 번만 반영한다. cash proceeds에 이미 반영된 debt transfer를 divestiture cash flow에 다시 더하지 않는다. proceeds 사용의 효과를 asset 매각 자체의 가치와 분리한다.

### 13.3 Lost cash flow와 stranded cost

- 매각되는 revenue·margin·working capital·capex
- parent가 계속 부담하는 corporate function·lease·IT·brand
- procurement·cross-selling·funding dis-synergy
- TSA income/cost와 종료 timing
- pension·guarantee·indemnity·environmental liability

공개 segment cost가 없으면 avoidable/unavoidable range와 break-even stranded cost를 제시한다.

### 13.4 Spin-off

- parent와 separated entity standalone financials
- debt·cash·pension·shared service allocation
- one-time separation cost
- dis-synergy와 management focus
- capital structure·liquidity·credit impact
- SOTP와 시장 multiple의 적용 차이

시장가치 재평가를 자동 가치창출로 넣지 않는다. cash flow·capital structure·execution과 별도 해석한다.

### 13.5 Closure·abandonment

- salvage/asset sale·working-capital recovery
- shutdown·decommission·employee/customer cost
- contract termination·warranty·remediation
- avoided loss·maintenance capex
- future option을 포기하는 비용

사업을 닫으면 회계손실이 발생해도 incremental NPV가 양수일 수 있고, 반대로 일회성 이익이 있어도 장기 현금흐름을 훼손할 수 있다.

### 13.6 IFRS 5 overlay

공개 actual이 held for sale 또는 discontinued operation으로 분류되면 둘을 같은 판정으로 합치지 않고 원 공시 표시를 반영한다. held for sale은 현재 상태로 즉시 매각 가능하고 매각이 highly probable한지 등 IFRS 5 기준을 먼저 확인한다. discontinued operation은 이미 처분됐거나 held for sale인 component이면서 별도의 major line/geography, 그러한 처분의 단일계획 일부 또는 재매각만을 위해 취득한 subsidiary인지 추가 확인한다. 가상 divestiture에서 management commitment·sale probability·component 요건을 확인할 수 없으면 어느 분류도 선언하지 않는다. standalone normalization은 P3의 [JUDG] 분석조정이며 IFRS 5 분류결론이 아니다.

근거: [IFRS 5 Non-current Assets Held for Sale and Discontinued Operations](https://www.ifrs.org/issued-standards/list-of-standards/ifrs-5-non-current-assets-held-for-sale-and-discontinued-operations/)

### 13.7 Divest no-go

아래 상태는 P3가 공개자료 범위에서 divest를 추천·release하지 않는 조건이다. retained liability·stranded cost·buyer/approval path가 비공개라 결론을 좌우하면 실제 거래 불가를 단정하지 않고 INSUFFICIENT_PUBLIC_EVIDENCE와 diligence request로 표시한다.

- after-tax net proceeds가 lost value와 separation downside를 보상하지 못함
- retained liability와 stranded cost가 관측불가인데 결론을 결정 — INSUFFICIENT_PUBLIC_EVIDENCE
- remaining company의 liquidity·scale·regulatory requirement가 훼손
- 공개자료로 확인된 buyer/approval/contract path가 실행불가능함. 미공개 조건이면 INSUFFICIENT_PUBLIC_EVIDENCE

### 14.5 Capital return

[JUDG] P3에서 dividend·buyback은 reinvestment·liquidity·leverage·거래가격과 함께 비교하는 하나의 capital-allocation alternative다. 보편적 residual rule로 가정하지 않는다.

- liquidity·debt·regulatory capital

- shareholder tax·distribution certainty — 공개자료 범위

### 14.6 Deleveraging

- pre-tax interest saving − 실제 공제가능한 cash-tax shield 감소 = after-tax interest saving
- distress/refinancing risk 감소
- liquidity와 maturity 개선
- reinvestment·capital return의 opportunity cost

FCFF/WACC로 operating value를 평가하고 funding effect를 WACC·capital structure에 이미 반영했다면 interest saving·tax shield를 operating cash flow에 다시 더하지 않는다. APV·FCFE 등 별도 접근을 쓸 때만 동일 basis로 한 번 반영한다. deleveraging의 가치는 단순 interest saving 외에 risk·optionality로 설명하되 중복 할인하지 않는다.

## 15. Scenario·sensitivity·break-even·decision rule

### 15.1 Scenario 설계

scenario 수를 고정하지 않는다. 서로 다른 경제적 경로만 유지한다.

- demand/adoption path
- price/take rate/margin path
- cost·capacity·working-capital path
- timing·approval·integration path
- funding·rate·FX path
- exit/terminal path

서로 의존하는 변수를 독립적으로 임의 조합하지 않는다. coherent narrative와 source/assumption을 연결한다.

### 15.2 Sensitivity anchor

범위는 다음에서 도출한다.

- 역사적 공개분포와 cycle
- company guidance·공개 transaction range
- peer fundamentals·market-implied expectation
- contract·regulatory boundary
- economic break-even·liquidity/no-go

단순 ±10% 같은 값을 표준처럼 쓰지 않는다.

### 15.3 Break-even

NPV=0, liquidity minimum, covenant/capital boundary 또는 alternative indifference가 되는 값을 역산한다.

- offer/entry price
- revenue·volume·adoption
- margin·unit cost
- synergy 규모·시작 지연·duration
- integration/separation cost
- cannibalization
- capex·working capital
- funding rate·FX
- terminal/exit

EPS break-even은 별도 communication table로만 두고 value gate로 승격하지 않는다.

### 15.4 Cash trough

~~~text
Cash_t
= Cash_(t−1)
+ Operating cash flow_t not included in the lines below
− Investment/transaction cash outflow_t not included elsewhere
+ Financing cash inflow_t not included elsewhere
− Financing repayment/distribution cash outflow_t not included elsewhere
~~~

reported IAS 7 분류는 source 그대로 보존하고, 이 cash-trough bridge의 analyst classification과 mapping을 별도 기록한다. interest·dividend·transaction cash가 reported operating cash flow와 financing/distribution line에 중복되지 않게 source_id별로 한 번만 배치한다. 최저 cash 시점, required funding, refinancing concentration과 recovery path를 option별로 비교한다.

### 15.5 Real option·irreversibility

- defer: 정보가 더 생길 때까지 기다림
- stage: milestone별 commitment
- expand: upside에서 capacity 확대
- contract: downside에서 규모 축소
- abandon: salvage를 받고 중단
- switch: input·channel·technology 전환

option value를 정교한 수식으로 계산할 근거가 없으면 decision tree, NPV before/after flexibility와 qualitative restriction으로 제시한다.

### 15.6 Risk·opportunity register

| ID | Option | Risk/opportunity | Public evidence | Mechanism | Financial line | Scenario | Break-even/trigger | Mitigation/next evidence | Proposed role |
|---|---|---|---|---|---|---|---|---|---|

확률을 모르면 임의 probability로 expected value를 만들지 않는다. conditional path와 break-even으로 대체할 수 있다.

### 15.7 Alternative comparison

| 대안 | Incremental NPV/range | Cash trough·funding | ROIC/IRR 보조 | Downside | Optionality | Strategic rationale | Key unknown | Break-even | Decision condition |
|---|---:|---|---|---|---|---|---|---|---|

가중 총점은 사용하지 않는다. 한 대안이 값은 높아도 non-negotiable constraint를 위반하면 제외한다.

### 15.8 조건부 decision state

- ANALYST_PREFERRED: 공개자료 기준 가치·현금·제약 gate를 통과하고 분석대안 중 우월
- ANALYST_PREFERRED_IF: 특정 price·milestone·funding·approval 가정에서만 우월
- DEFER_AND_TEST: 정보가치가 기다림 비용보다 크고 milestone이 정의됨
- P3_DO_NOT_RECOMMEND: 공개자료상 경제적 break-even 또는 확인된 hard constraint를 위반
- INSUFFICIENT_PUBLIC_EVIDENCE: 공개정보 gap이 결론을 결정

각 state는 official taxonomy가 아니라 P3의 [JUDG] communication convention이다.

### 15.9 Decision rule

~~~text
If public-data rights/vintage fail
  → do not release.
Else if critical constraint is violated
  → P3 does not recommend; redesign the analyst case.
Else if evidence gap determines ranking
  → insufficient evidence / request real diligence.
Else compare the supportable incremental value measure (NPV when reliable), cash/liquidity, downside and optionality.
Then issue an analyst-preferred conditional state with price/milestone triggers.
~~~

## 17. 검증·outcome analysis·monitoring

### 17.1 검증 선언

검증 전에 다음을 기록한다.

- intended use와 prohibited use
- material output·failure mode
- formula/accounting/source tests
- benchmark·outcome method
- reviewer의 독립성·범위
- pass/fail 또는 limited-use rule

검증범위는 모델 복잡성·중요도·오판손실에 비례한다. 고정 test 수나 오차율을 표준으로 두지 않는다.

### 17.2 Known-answer formula test

작은 synthetic fixture로 활성화한 module의 계산만 exact check한다. 적용하지 않은 M&A·PPA·financing·synergy module은 N/A와 제외 이유를 test register에 남기고 억지로 계산하지 않는다.

- incremental CF가 option − status quo와 일치
- NPV를 사용하는 경우 독립 계산과 일치
- financing/transaction module이면 Sources = Uses
- integrated-statement module이면 Assets = Liabilities + Equity
- 관련 schedule이 있으면 cash·debt·share count roll-forward
- Article 11 pro forma module이면 historical + Transaction Accounting Adjustments + 해당 시 Autonomous Entity Adjustments = filed pro forma이고, Management’s Adjustments는 notes-only reconciliation
- M&A transaction module이면 transaction price↔EV↔equity↔closing cash Sources/Uses를, IFRS 3 PPA module이면 consideration+NCI+prior interest−공개 acquisition-date fair-value net assets↔공개 goodwill을 각각 별도 reconcile
- synergy module이면 synergy·integration·tax timing
- buy module이면 max price에서 NPV=0
- break-even solver의 objective=0

합성 test는 formula correctness만 검증한다. input reasonableness와 실제 예측력을 검증하지 않는다.

### 17.3 Cross-source reconciliation

- 회사 IR ↔ DART/KIND/KRX 또는 SEC filing
- API/XBRL extraction ↔ 원문 filing
- announcement ↔ agreement/proxy/S-4/주요사항보고서 ↔ closing filing
- historical P&L/BS/CF ↔ pro forma columns ↔ sources/uses
- deal value ↔ consideration components ↔ share count/debt/cash
- announced synergy ↔ 후속 공시된 realized/updated claim

차이는 source priority, scope, date, unit 또는 restatement으로 설명한다.

### 17.4 Benchmark

benchmark는 목적에 따라 선택한다.

- status quo
- build·partner·buy·divest 중 next-best alternative
- 회사의 공개 target/guidance
- analyst precommitted forecast
- comparable company/action
- market-implied expectation

benchmark의 선택 자체가 결론을 만들 수 있으므로 제외대안과 한계를 기록한다.

### 17.5 Historical ex-ante outcome

1. information cutoff와 frozen raw snapshot을 확정
2. 당시 공개정보로 standalone·option·decision을 생성
3. prediction·condition·monitoring metric을 immutable하게 저장
4. 이후 public outcome을 별도 dataset으로 수집
5. scope·accounting·FX·M&A·restatement 변화 조정
6. forecast error, thesis hit/miss, decision trigger와 limitation 평가

미래정보를 원 model에 역주입하지 않는다.

### 17.6 Outcome label

- DESCRIPTIVE: 공개 전후 변화만 기술
- BENCHMARKED: peer/status quo 대비 변화
- CONTRIBUTION_EVIDENCE: 공개된 mechanism·milestone·alternative explanation을 함께 검토
- CAUSAL_ESTIMATE: estimand, treatment timing, comparator, identification assumptions, anticipation·spillover, reporting-scope change와 placebo·robustness·sensitivity를 사전 정의하고 credible counterfactual을 구축했을 때만

위 요건을 충족하지 못하면 더 낮은 label로 내린다. post-deal consolidated·segment 공시에서 target 또는 synergy를 분리할 수 없으면 realized synergy나 거래의 causal effect를 주장하지 않는다. 대부분의 개인 P3 거래사례는 DESCRIPTIVE 또는 BENCHMARKED에 머문다.

근거: [HM Treasury — The Magenta Book](https://www.gov.uk/government/publications/the-magenta-book/magenta-book-central-government-guidance-on-evaluation-html). 이는 기업거래 규정이 아니라 counterfactual·대체설명·인과강도 표기의 유사 방법론으로만 사용한다.

### 17.7 사후 공개지표

case에 맞는 것만 사용한다.

- reported synergy target의 변경·철회·달성 주장
- segment revenue·margin·cash flow·ROIC
- integration/restructuring charge
- goodwill·intangible·impairment
- capex·working capital·cash conversion
- net debt·coverage·rating·capital/liquidity
- customer·capacity·product milestone
- subsequent divestiture·closure·additional investment

impairment, 주가 또는 single KPI를 자동 성공·실패판정으로 쓰지 않는다.

### 17.8 Monitoring·revalidation trigger

- 새 공시·정정·거래조건 변경
- approval·close·termination
- material financing·rating·capital change
- key driver가 break-even을 통과
- synergy/integration milestone 지연
- segment/reporting boundary 변경
- license/source API 변경
- model assumption·formula·method 변경

trigger가 발생하면 새 version을 만들고 이전 recommendation을 조용히 덮어쓰지 않는다.

### 17.9 Independent review

independent reviewer는 해당 model 작성과 core assumption 설정에 참여하지 않은 사람이어야 한다. 그런 reviewer를 확보하지 못하면 검토를 self-review로 표시하고 independent validation·effective challenge를 주장하지 않으며 release snapshot을 limited-use로 제한한다.

reviewer는 최소한 다음을 challenge한다.

- 데이터 접근권한·license·vintage leakage
- 대안·counterfactual의 완전성과 실행가능성
- incremental identity·tax·working capital·capex
- financing·EV/equity·consideration·share count
- synergy·integration double count
- pro forma와 forecast의 의미
- discount rate·terminal·max price·break-even
- 인과·성과·실제 경험 과장

finding, severity, response, retest와 remaining restriction을 보존한다.

## 18. 실행계획: 달력이 아닌 dependency gate

### Phase A — 목적·case·민간 data feasibility

할 일:

- Mode A/B/C 후보와 Gate A–H
- source·transaction one-slice pilot
- core/optional/prohibited scope

완료조건:

- 공개 source만으로 decision→model→validation 경로가 가능한 case가 선택됨

### Phase B — Semantic·source·vintage foundation

할 일:

- assumption·license register

완료조건:

- PUBLIC_FACT·management view·analyst assumption·outcome이 분리됨

### Phase C — Standalone·status quo

할 일:

- historical normalization
- driver·P&L·BS·CF·capital structure
- status-quo forecast
- counterfactual·scope limitation

완료조건:

- standalone statements와 cash가 reconcile됨
- status quo가 공개근거·가정과 연결됨

### Phase D — Alternative models·transaction·pro forma

할 일:

- build/partner/buy/divest 등 선택 대안
- incremental after-tax CF
- consideration·sources/uses·financing — 활성화한 대안에 해당할 때
- accounting pro forma와 analyst combined case — 활성화한 대안에 해당할 때
- IFRS overlay — 해당 시

완료조건:

- 모든 대안이 같은 convention에서 비교됨
- factual transaction adjustment와 forward-looking assumption이 분리됨

### Phase E — Valuation·risk·decision

할 일:

- 공개근거로 가능한 NPV와 적합한 다른 value measure
- scenario·sensitivity·cash trough
- maximum price 또는 선택 대안의 equivalent break-even — 해당 시
- constraint·risk/opportunity
- conditional recommendation·no-go

완료조건:

- 값·현금·제약·optionality가 한 decision rule로 연결됨
- strongest counterargument와 insufficient-evidence state가 있음

### Phase F — Validation·communication·release

할 일:

- known-answer·reconciliation·benchmark
- historical outcome 또는 monitoring specification
- independent review·retest
- memo·read-only snapshot·handover
- license·claim·privacy check

완료조건:

- 모든 non-waivable gate와 활성화 module의 gate를 통과함. limited-use가 허용되는 non-core gap은 영향이 격리되고 restriction이 전면 표시됨
- source→model→decision을 다른 사람이 재현 가능

### 일정 산정

고정 주수로 약속하지 않는다.

1. source slice의 실제 수집·정규화·reconciliation 시간을 측정
2. 거래문서·segment·option 수와 review complexity를 파악
3. critical dependency와 external release lag를 표시
4. core와 optional 산출물을 분리
5. uncertainty reserve의 이유를 기록

dashboard나 deck부터 만들지 않는다. Phase A·B가 끝나기 전에는 정밀 model을 확장하지 않는다.

## 19. 비보상적 release gate

중요 gate가 실패하면 가중점수로 상쇄하지 않는다. R1 data rights, R10 privacy·license·claim integrity, 그리고 활성화 module의 핵심 계산 identity·reconciliation 실패는 non-waivable이며 not for release다. 그 밖의 gap은 결론에 미치는 영향이 격리되고 어떤 recommendation도 그 gap에 의존하지 않으며 제한이 전면 공개되는 경우에만 limited-use/illustrative only를 허용한다. 선택하지 않은 module은 N/A와 근거를 기록한다.

### Gate R1 — 민간 접근가능성·data rights

- 모든 core input·transaction term에 원문 URL/ID, release timestamp·timezone·시장 이용가능성, access class와 license가 있다.
- 고용·NDA·data room·감독권한 없이 다시 확보 가능하다.
- 무료 공식·회사 공개자료만으로 핵심 결론이 재현된다.
- commercial source와 synthetic fixture가 core fact에서 분리된다.
- AI 요약이 유일한 actual 근거가 아니다.
- 저장·가공·재배포 권리가 명확하지 않은 원문·row·derived data는 snapshot에 복제하지 않고 locator·hash·재현절차·합법적 공개 대체자료만 둔다.

### Gate R2 — Decision semantic·vintage

- perspective, status quo, next-best alternative, as-of와 scope가 명확하다.
- announcement·filing·approval·close·outcome date가 분리된다.
- public fact·management view·external estimate·analyst assumption·outcome이 분리된다.
- first-filed·restated·latest와 model revision이 구분된다.
- ex-ante version에 hindsight가 없다.
- cutoff 당일 공개시각·이용가능성을 입증할 수 없으면 제외하거나 보수적인 다음 공개기간으로 처리한다.

### Gate R3 — Incremental cash-flow integrity

- option − status quo identity가 맞는다.
- after-tax, capex, Δ operating net working capital, terminal/exit와 timing이 포함된다.
- sunk cost가 제외되고 opportunity cost·cannibalization이 검토된다.
- initial project/transaction outlay와 consideration이 선택한 NPV basis에서 한 번만 반영된다.
- project와 financing cash flow가 이중계산되지 않는다.
- 선언한 model scope의 cash·관련 balance schedule이 reconcile되고, integrated P&L·BS·CF를 활성화한 경우 세 재무제표가 reconcile된다.

### Gate R4 — Alternative comparability

- 공개정보상 배제되지 않은 analyst-defined 대안이 동일 as-of·scope·currency·tax·price basis에서 비교된다. 실제 조직의 capability·mandate·협상·비공개 승인 실행가능성은 별도 limitation이다.
- mutually exclusive·compatible·sequential 관계가 표시된다.
- 공개자료가 없는 대안을 허위 점추정치나 score로 채우지 않는다.
- defer·stage·abandon option과 기다림 비용을 검토한다.

### Gate R5 — Transaction·pro forma·accounting

- transaction/pro forma/PPA module을 선택하지 않았으면 N/A 이유가 기록된다.
- standalone, transaction-accounting pro forma, forward-looking analyst case가 분리된다.
- 해당 시 Autonomous Entity Adjustments와 선택적 Management’s Adjustments reconciliation이 별도 표시된다.
- transaction price·transaction EV·equity purchase price·closing cash paid·cash Sources/Uses가 reconcile된다. 별도로 IFRS 3 적용 시 consideration transferred+NCI+previous interest−acquisition-date fair-value identifiable net assets가 공개 PPA/goodwill에 reconcile된다.
- historical + Transaction Accounting Adjustments + 해당 시 Autonomous Entity Adjustments = filed pro forma가 맞고 adjustment가 source/footnote에 연결된다. Management’s Adjustments는 filed pro forma total에 합산하지 않는다.
- 실제 SEC Management’s Adjustments를 인용하면 reasonable basis, 관련 dis-synergy 동시 표시, 역사적 비용 상한, basis·material limitation·assumption·uncertainty·계산·timing 공시를 원문에서 확인한다.
- IFRS overlay는 illustrative이며 final PPA·impairment·IFRS 5 conclusion으로 과장하지 않는다.

### Gate R6 — Synergy·integration·reasonable basis

- synergy·integration·separation module을 선택하지 않았으면 N/A 이유가 기록된다.
- 회사 발표 synergy와 analyst case, realized outcome이 분리된다.
- revenue·cost·capex·working-capital·tax, gross/net, pre/post-tax, timing이 있다.
- dis-synergy·integration·separation cash cost와 dependency가 포함된다.
- standalone improvement·synergy·PPA의 double count가 없다.
- 공개근거가 없으면 range·break-even·not observable로 표시한다.
- acquisition transaction cost, financing issuance cost와 integration/restructuring cost가 별도 schedule에 있고 각 현금효과가 한 번만 반영된다.

### Gate R7 — Financing·liquidity·capital

- financing module을 선택하지 않았으면 N/A 이유가 기록되고, 선택한 경우 Sources = Uses와 cash·debt·share count roll-forward가 맞는다.
- funding rate·maturity·dilution·liquidity·coverage·capital constraint가 연결된다.
- 공개되지 않은 covenant·cash floor·regulatory limit를 fact로 만들지 않는다.
- financing mix를 operating value의 자동 원천으로 취급하지 않는다.
- [JUDG] 규제 금융회사는 debt·cash·interest·regulatory capital의 operating 성격을 판정하고, 해당 시 equity-basis valuation과 감독기관 공식 규정·회사 공시에 따른 CET1/RWA·solvency·분배가능자본 제약을 사용한다.

### Gate R8 — Value·downside·decision

- cash-flow와 discount-rate basis가 일치한다.
- incremental cash flow를 신뢰성 있게 모델링할 수 있으면 NPV를 우선하고, 그렇지 않으면 목적에 맞는 value measure·break-even·미산출 이유가 있다. IRR·ROIC·payback·EPS를 사용하면 한계가 적혀 있다.
- [JUDG] 규제 금융회사에는 비금융 FCFF/WACC·net-debt EV bridge를 자동 적용하지 않고 FCFE·dividend·residual-income·distributable-capital 중 선택한 equity framework의 basis를 일치시킨다.
- maximum price 또는 선택 대안의 equivalent break-even과 cash trough가 해당 시 있다.
- terminal·exit·discount rate·synergy가 결론을 지배할 때 reverse/sensitivity가 있다.
- conditional recommendation, no-go와 strongest counterargument가 있다.

### Gate R9 — Validation·effective challenge

- synthetic known-answer와 public-source reconciliation이 통과한다.
- source→mapping→standalone→incremental→활성화한 transaction/pro forma→valuation→decision을 추적할 수 있다.
- benchmark/outcome 범위와 인과 한계가 사전 기록된다. CAUSAL_ESTIMATE이면 estimand·timing·comparator·identification·anticipation/spillover·scope와 placebo/robustness/sensitivity 요건을 충족한다.
- post-deal 공시로 target·synergy를 분리할 수 없으면 realized synergy·causal claim을 하지 않는다.
- model·core assumptions 작성에 참여하지 않은 reviewer의 finding·response·retest·remaining restriction이 있다. 확보하지 못하면 self-review·limited-use로 표시한다.
- memo·model·read-only snapshot의 숫자가 일치한다.

### Gate R10 — Claim integrity·publication

- personal project·public-source desktop diligence임이 첫 화면에 보인다.
- 실제 투자위·board·경영진 지원, full diligence, fairness opinion, audited model로 표현하지 않는다.
- EPS·주가·goodwill impairment·synthetic test를 가치창출·실제성과로 과장하지 않는다.
- 라이선스 제한 원문·개인정보·비밀키가 없다.
- 불리한 결과·미산출·데이터 gap·판단을 바꿀 trigger가 공개된다.

## 22. 이력서·면접 표현

### 22.1 이력서 한 줄 구조

> 개인 프로젝트로 [기준일] 공개 공시·거래·시장자료를 정규화해 [의사결정]의 status quo와 [대안]을 비교하고, 증분 세후현금흐름·[transaction/financing/pro forma]·scenario·break-even을 연결한 조건부 의사결정 모델과 검증가능한 memo를 제작.

실제 case 완료 후에만 구체적 결과를 넣는다.

- input source와 as-of
- 모델링한 대안
- 검증한 identity·reconciliation
- NPV range·max price·break-even 같은 실제 산출값
- public-data·counterfactual 한계

### 22.2 면접 구조

1. 왜 이 decision question을 선택했는가
2. 공개자료만 쓰는 제약이 scope를 어떻게 바꿨는가
3. status quo와 대안을 어떻게 정의했는가
4. incremental cash flow에서 가장 중요한 누락위험은 무엇이었나
5. accounting pro forma·synergy·financing을 어떻게 분리했나
6. 어떤 break-even에서 결론이 바뀌었나
7. reviewer challenge로 무엇을 수정했나
8. 실제 조직이라면 어떤 비공개 diligence를 추가 요청할 것인가

### 22.3 피해야 할 표현

- 인수기회를 발굴했다 → 공개된 case에서 screening framework를 적용했다
- 기업가치를 확정했다 → 공개정보와 명시가정으로 valuation range를 추정했다
- 시너지를 검증했다 → 회사 발표·analyst scenario·공개 outcome을 분리했다
- 경영진 의사결정을 지원했다 → 경영진용 형식을 모사한 개인 decision memo를 만들었다
- due diligence를 수행했다 → public-source desktop/preliminary diligence를 수행했다
- 거래가 가치를 창출했다 → 당시 공개정보로 조건부 NPV와 반전조건을 산출했다
- PPA를 완료했다 → 공개자료 기반 illustrative PPA bridge를 만들었다
- 손상을 예측했다 → 공개된 CGU·recoverable-amount 가정의 sensitivity를 재현하거나 analyst recoverability stress를 수행했다
- 모델이 정확했다 → 선언한 benchmark·기간·자료범위에서 error와 limitation을 측정했다

- 금융문제를 구조화한 경험
